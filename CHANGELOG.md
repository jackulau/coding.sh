# Changelog

All notable changes to coding.sh are listed here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions will
follow [Semantic Versioning](https://semver.org/) from the first npm release.

Each release opens with a short summary. The list under it has one line per change,
grouped by area, with links to the docs for the details.

## [0.1.5] - Unreleased

### Fixed

- **Sessions.** `sessions --where id:<id>` and `export --where id:<id>` find a subagent's session, such as a Claude Code workflow agent's, as `show <id>` does. Both commands leave out subagents unless you pass `--subagents`, and that default hid every session the query named. A query with `id:`, `parent:`, `is:root` or `is:child` now decides that itself, so `--where is:child` lists subagents too. [Query and export](https://github.com/jackulau/coding.sh/blob/main/docs/reference/query.md#filter-with---where).
- **Workflows.** A Claude Code workflow run that is still going is named by its script's `meta.name`, read from the copy of the script Claude Code keeps in the session's `workflows/scripts/` folder, instead of by its `wf_…` id. Claude Code writes the record, which held the only name coding.sh read, when the run ends. `workflows import` reads runs it stored before this fix again once. [Workflows](https://github.com/jackulau/coding.sh/blob/main/docs/design/workflows.md#21-claude-code-workflows).
- **Capture.** The hook no longer reads `.git` on session-start and prompt events, which made each of those hook calls about 3.5 ms slower than in 0.1.2 in a repo with a 1 MB `packed-refs`. Ingest takes a hook session's start commit from the reflog again, and still uses the HEAD a 0.1.3 or 0.1.4 hook recorded. `CODING_SH_NO_GIT_HEAD` has nothing left to turn off. [Architecture](https://github.com/jackulau/coding.sh/blob/main/docs/design/architecture.md#spool-the-hot-path).
- **Harness A/B.** `compare` counts cache reads and writes in `tokens / run`. With prompt caching the row tracked output tokens only, so a harness that cost 40% more could read as 11% more tokens. [Harness A/B](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#harness-ab).
- **Privacy.** `coding.sh purge` no longer reports `Integrity check failed` and exits 1 after every purge. The check asked SQLite's full-text search to find an entry for every event, but events with no text, such as a session start or a model call, are never indexed. It now checks that the index is sound and holds exactly the events with text. Search was not affected. [Privacy](https://github.com/jackulau/coding.sh/blob/main/docs/guides/privacy.md#privacy).
- **Harness A/B.** `compare` leaves out `time to first derail` when no run in either arm derailed, where it only repeated the session length. [Derails](https://github.com/jackulau/coding.sh/blob/main/docs/guides/explore.md#derails).

## [0.1.3] - 2026-11-08

Sessions read back from Claude Code and Codex transcripts keep more of what the agent recorded.

### Added

- **Docs.** Two guides for one agent each. coding.sh with T3 Code covers what is read from T3 Code's local store for each agent it runs, and how to turn a thread into an eval run by Codex or Claude Code. coding.sh with Pi covers the Pi extension, Pi's own cost per model call, and evals with `--agent pi`. [T3 Code](https://github.com/jackulau/coding.sh/blob/main/docs/use-cases/t3-code.md), [Pi](https://github.com/jackulau/coding.sh/blob/main/docs/use-cases/pi.md).
- **Workflows.** `workflows stats --json` gives each per-agent row the agent id, the attempt (a label run again after a resume is attempt 2) and how it ended (`endReason`: ok, failed, cancelled, superseded, null, schema-retry, …), so two agents with the same label can be told apart. The text table adds `#2` to a re-run label. [Workflows](https://github.com/jackulau/coding.sh/blob/main/docs/design/workflows.md#4-metrics).
- **Improve.** `improve` and the MCP `improve` tool list what lost prompt cache cost, from the cache breaks ingest already stored: the extra dollars, their share of the spend, which sets the severity so the item ranks against the others by cost, and a fix per cause, costliest first. [Improve](https://github.com/jackulau/coding.sh/blob/main/docs/guides/improve.md#1-see-what-to-fix-first).
- **Sessions.** A new `coding.sh tree <session|run>` command shows a whole multi-agent run as one tree: the top-level agent, every subagent it spawned, and their subagents, with per-node model, cost, tokens, duration and tool calls, the run's rolled-up totals, the worst flag across the loop, and which subagent to fix first. A fan-out of separate agent processes groups into one run when they share `CODING_SH_RUN_ID`. The viewer serves it at `/api/sessions/{id}/tree` and the MCP `session_tree` tool returns it for your agent. It is built from the parent links capture already records, so no session re-folds. [Explore](https://github.com/jackulau/coding.sh/blob/main/docs/guides/explore.md).
- **Capture.** A tool output the agent cut before the model saw it is marked on its `tool.end` as `payload.cut`: Codex's head-and-tail cut of a long command or code-mode result (with the original token count, and `jsonBroken` when cut JSON no longer parses), and Claude Code's `<persisted-output>` preview of a result saved to a file (with its size and path). Backfilled sessions only for now; a hook-captured call keeps the hook's copy. [Adapters](https://github.com/jackulau/coding.sh/blob/main/docs/ADAPTERS.md#known-breakage-to-design-around).
- **Capture.** API errors Claude Code retried keep what the transcript says about them: the HTTP status, the error type and class (`rate_limit`, `overloaded`, …), the rate limit that was hit (`seven_day`, `five_hour`), when it resets, how long Claude Code waited and which attempt it was. Before, every one was a bare "api error", so a three-day weekly-limit stall looked like one transient error. [Read API](https://github.com/jackulau/coding.sh/blob/main/docs/reference/api.md#get-apisessionsid).
- **Cost.** A Claude Code backfill keeps Claude Code's own cost tally (the transcript's `cost-state` line: total cost, API time and cost per model) on the session's `session.end` as `payload.reportedUsage`, so you can check the computed cost against it. It is never added to the session's cost. [Where cost comes from](https://github.com/jackulau/coding.sh/blob/main/docs/how-to/expensive-sessions.md#where-cost-comes-from).
- **Capture.** The hook records the repo root, HEAD commit and branch on session-start and prompt events, read from `.git` files without running git (worktrees, submodules, packed refs, detached and unborn heads). A hook session's start commit, which `eval new` starts from, is now the HEAD when the session started. Before, ingest looked it up in the reflog and, when the reflog had nothing, took the HEAD at ingest time. `CODING_SH_NO_GIT_HEAD=1` turns it off. [Configuration](https://github.com/jackulau/coding.sh/blob/main/docs/reference/config.md#capture).
- **Capture.** Before `coding.sh init`, a read now works with no setup: `usage`, `sessions`, `show` and the viewer import the Claude Code transcripts already on disk, so `coding.sh usage` shows your history straight away. Once the hooks are installed, live capture takes over and the transcripts are not re-read on every read. [Adapters](https://github.com/jackulau/coding.sh/blob/main/docs/ADAPTERS.md).
- **CI.** A GitHub Action in this repo (`uses: jackulau/coding.sh@<ref>`) installs coding.sh, runs one command such as `eval run triage --yes` or `exp compare base head --margin 0.05`, writes the report to the step summary and to one pull request comment that later runs edit, and fails the job when the command fails. `eval run --summary <file>` appends the report as Markdown, and the workflow `eval init` prints uses the action. [Catch a regression in CI](https://github.com/jackulau/coding.sh/blob/main/docs/how-to/ci-regressions.md).
- **MCP.** A `harness_audit` tool and a `trim` prompt let your agent audit your setup and trim what goes unused: each memory file, CLAUDE.md, AGENTS.md, rule and skill with the sessions that loaded and read it and its load tokens per session, unused ones first. With `check: true` it runs `refine check` on your uncommitted edits, and it returns the `refine run` command instead of running it. Shorter shared argument descriptions keep the tool list within its byte budget. [Memory and instruction files](https://github.com/jackulau/coding.sh/blob/main/docs/guides/explore.md#memory-and-instruction-files).
- **Harness.** `harness audit` warns about Claude Code subagent files whose `tools:` frontmatter is a map such as `edit: false`, which leaves the subagent with no tools, and gives the `disallowedTools:` line to use instead. `--json` lists them under `agentFiles`. [Explore guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/explore.md#memory-and-instruction-files).
- **Capture.** `coding.sh statusline` prints a Claude Code status line — model, this session's cost, today's cost and the worst failure flag — from your stored sessions. `statusline install` wires it into the Claude Code `settings.json` and `statusline uninstall` restores the previous one byte-for-byte. [Status line how-to](https://github.com/jackulau/coding.sh/blob/main/docs/how-to/status-line.md).
- **Refine.** `refine test --suite` and `refine run --suite` take `--reuse baseline` (or `both`), copying an earlier round's finished runs of the unchanged base arm instead of running the agent again, so a long climb spends roughly half the agent sessions. Reuse is keyed by content like `compare --reuse`, copies count `$0` toward `--max-cost`, and the round warns that the reused arm did not run interleaved; the verdict is unchanged because the copied runs are identical. [Climbing on an eval suite](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#climbing-on-an-eval-suite).
- **Cache.** `coding.sh usage --cache` turns the cache rate into advice: per agent, model, day or repo it shows the hit rate, cache-read vs cache-write tokens, the read-to-write ratio (below 1:1 you wrote more cache than you read back), the prompt-cache breaks and what they cost, and names the break causes to change — compaction, a mid-session model switch, or an idle gap past the cache lifetime. Every number is a captured token count or the per-call-priced extra the breaks cost; there is no blended-rate guess. A session that wrote a cache of at least one block over three or more turns but read back fewer tokens than it wrote is tagged `cache:low`, and `--where cache.breaks>0`, `cache.lost` and `cache.cost` query and sort on the breaks (`coding.sh sessions --where 'cache.breaks>0 sort:-cache.cost'`). `exp compare` gains `cache breaks / run` and `cache waste / run` metrics so an A/B shows whether a setup change reused the cache better, and the viewer shows the read-to-write ratio next to a session's cache rate. [Explore](https://github.com/jackulau/coding.sh/blob/main/docs/guides/explore.md).
- **Capture.** Claude Code's `model_fallback` and `model_refusal_fallback` transcript records (the main model was overloaded and Claude Code moved to `--fallback-model`, or a refusal went to another model) become a `model.fallback` notification with both models and the trigger, and tag the session `model:fallback`. [Adapters](https://github.com/jackulau/coding.sh/blob/main/docs/ADAPTERS.md#known-breakage-to-design-around).
- **Cache.** Idle cache breaks say where the wait was, in `stats.cacheBreaks.byIdle` and as one `usage --cache` line each: a foreground tool call that ran past the cache lifetime (`wait`: keep foreground waits under the 5-minute subagent cache lifetime and poll in chunks), a subagent idle between turns (`subagent`), or the main session idle between turns (`away`: unavoidable while you are away; the 1-hour cache helps if you return often). [Read API](https://github.com/jackulau/coding.sh/blob/main/docs/reference/api.md#get-apisessionsid).

### Changed

- **Site.** The top bar links only Docs and Changelog. The comparison pages stay in the docs sidebar and the blog stays in the footer. [Site](https://coding.sh/).
- **Setup.** `coding.sh init` ends by saying that recording starts with the next agent session, since an agent loads hooks when a session starts. Once capture is set up, an empty store no longer sends you back to `init`: `show latest`, `sessions`, `status`, `improve`, the MCP `status` and `session_current` tools, and the viewer ("Waiting for your first session") say to start a new agent session and to run `coding.sh doctor` if none shows up. [Install](https://github.com/jackulau/coding.sh/blob/main/docs/guides/install.md#what-init-changes)
- **Setup.** The installer run without a terminal (an agent's shell, CI) and without `CODING_SH_YES=1` says no agent was set up and names `coding.sh init --dry-run` and `coding.sh init --yes`, instead of `coding.sh`, which only prints help there. [Install](https://github.com/jackulau/coding.sh/blob/main/docs/guides/install.md#installer)
- **Improve.** `improve` and the MCP `improve` tool leave out headless sessions (`claude -p`, an Agent SDK, `codex exec`: `stats.launch` is `"headless"`), say how many they left out, and count them with `--headless` (`headless: true`). Before, one-shot scripts, judges and evals filled the report with issues a CLAUDE.md line does not change. [Improve](https://github.com/jackulau/coding.sh/blob/main/docs/guides/improve.md#1-see-what-to-fix-first).
- **Evals.** `compare --reuse baseline` says in its help and docs that it copies the runs of an `eval run` too, so a suite's baseline from `eval run` is not paid for again in each comparison. [Evals](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#reuse-finished-runs).
- **Capture.** Hooks append to one spool file per agent per UTC day (`spool/<agent>/<day>.jsonl`, continued in `<day>.1.jsonl` past 64 MB) instead of one file per hook call. A busy day used to leave about 11,000 files, each with an ingest cursor that every ingest and `gc` looked up. `gc` keeps the current day's file, and removes a deleted file's cursor instead of setting it to 0. [Architecture](https://github.com/jackulau/coding.sh/blob/main/docs/design/architecture.md#spool-the-hot-path).
- **Sessions.** `model:switch` fires on every mid-session model change the agent recorded as a fallback, a switch and back included, and on any model change inside a subagent; before, only a main-thread hand-over for good counted. `stats.modelSwitch` adds the fallback `reason`, `subagent`, `count`, `switchedCalls` and `extraUsd`: what the calls on the other model cost over the first model's list prices. [Concepts](https://github.com/jackulau/coding.sh/blob/main/docs/concepts.md).

### Fixed

- **Workflows.** A Claude Code workflow agent you stopped is `cancelled`, and one a resume re-ran under the same label is `superseded`, instead of `failed` with "no result recorded". `workflows show` and `stats` list them apart from failures and leave them out of the failure rate (`cancelledAgents`, `supersededAgents` in `--json`). On a run stopped and resumed twice, all 7 "failures" were these. [Workflows](https://github.com/jackulau/coding.sh/blob/main/docs/design/workflows.md#4-metrics).
- **Workflows.** The wall time of a Claude Code workflow stopped and resumed in the same run dir runs from the first launch to the last result. Before, it covered only the last segment (4h43m of a 6h43m run), so the critical path came out longer than the wall and parallelism and utilization were off. `workflows show` and `stats` add the active time without the gaps between segments (`activeMs`, `segments`), and parallelism and utilization use it. [Workflows](https://github.com/jackulau/coding.sh/blob/main/docs/design/workflows.md#4-metrics).
- **Workflows.** `workflows import`, and the import `workflows list` runs first, skip an unchanged run dir before reading its agent transcripts, and write each run's events to the index in a few large batches. On 16 synthetic runs with 470 MB of agent transcripts, a repeat import took 0.3 s instead of 13.6 s and a first import 19.5 s instead of 26.7 s. The host session's transcript is never read. [Workflows guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/workflows.md).
- **Workflows.** Cache hits on a Claude Code workflow resumed in the same run dir are read from the run's persisted record, since the journal writes no cache lines there. `workflows stats` showed 0 cache hits and no resume savings for a run whose record marks 11 agents cached; it now counts them and sums what they took when they ran as "resume saved", and `show` marks them "replayed on resume". [Workflows](https://github.com/jackulau/coding.sh/blob/main/docs/design/workflows.md#4-metrics).
- **Workflows.** `workflows show`, `stats` and the Gantt list a run's phases in the same order, by when each phase first started. Before, `stats` put phases the script dropped before a resume (such as Review and Verify) last. [Workflows](https://github.com/jackulau/coding.sh/blob/main/docs/design/workflows.md#4-metrics).
- **Workflows.** `workflows import` redacts Claude Code workflow agent transcripts before it stores them, with the same capture settings as ingest and backfill (redaction, `[capture] redactPatterns`, metadata mode). Before, agent prompts, replies and tool output went into the index and blob store unredacted. Re-import earlier runs with `--force` to redact them. [Privacy](https://github.com/jackulau/coding.sh/blob/main/docs/guides/privacy.md).
- **Workflows.** `coding.sh workflows import|show|stats` now shows cost for Claude Code Workflow runs. Claude Code transcripts carry tokens but no per-call cost, so each agent's model calls are priced from their tokens and the configured prices (as everywhere else in coding.sh), filling per-agent, per-phase and whole-run cost and `costShareByPhase`. Before, every captured workflow showed a dash for cost, hiding which stage spent the tokens. Re-import a run with `--force` to price one captured earlier. [Workflows](https://github.com/jackulau/coding.sh/blob/main/docs/design/workflows.md).
- **Setup.** `coding.sh init` started with `npx coding.sh` ends with `npx coding.sh ui` and `npx coding.sh improve` as the next commands. Before, it named `coding.sh ui`, which is not on your PATH until you install it. [Install](https://github.com/jackulau/coding.sh/blob/main/docs/guides/install.md#npm)
- **Setup.** `doctor` no longer reports an agent as hooked while it also says the hook is missing. Each agent row names the settings file it read, and says when that file's hooks run another coding.sh home's `hook.mjs` (another `HOME` or `CODING_SH_HOME`); `doctor --json` lists the files under `hookFiles`. `init` no longer skips an agent's hooks because a project already holds hooks for another home. [Troubleshooting](https://github.com/jackulau/coding.sh/blob/main/docs/troubleshooting.md#run-doctor).
- **Capture.** `ingest` and `ingest --backfill` no longer print a bare event count after their summary. `ingest --json` still carries the counts. [CLI reference](https://github.com/jackulau/coding.sh/blob/main/docs/reference/cli.md#codingsh-ingest).
- **Sessions.** A session that ran in the macOS temp dir (`/var/folders/<xx>/<yyy>/T`, where `claude -p` from a script often runs) has the repo name `tmp` in `repo:` queries and the repo facet, in SQLite and the Postgres and ClickHouse stores, instead of `T`. [Query](https://github.com/jackulau/coding.sh/blob/main/docs/reference/query.md).
- **Capture.** A vendor-shaped key whose value is plainly made up, such as `AKIAIOSFODNN7EXAMPLE`, `sk-ant-test-…`, `csh_ik_aaaa…` or `SECRETSECRETSECRET`, is still redacted but counts as `placeholder-key` and no longer tags the session `secret:exposed`. Before, working on code with test fixtures, coding.sh's own included, flagged sessions as leaking credentials. Random-looking keys count as before. `coding.sh ingest --rebuild` re-counts sessions already stored. [Privacy](https://github.com/jackulau/coding.sh/blob/main/docs/guides/privacy.md).
- **Improve.** A failed compound shell line counts against the part that failed: the one its error names, the tool whose error it is, the part `timeout` stopped, or the last part of a pipeline, and "compound command" when nothing singles one out. Before, it went under its first word, so `cat`, `for`, `sed`, `export` and even `--session` (from a line continuation) filled the list with errors from other tools, and a `cat` of a test log got the broken-setup verdict. [Improve](https://github.com/jackulau/coding.sh/blob/main/docs/guides/improve.md#1-see-what-to-fix-first).
- **Improve.** `improve`, `improve check` and the MCP `improve` and `harness_changes` tools redact secrets and email addresses in the prompts, error lines, commands and session titles they show. Before, an email address in a prompt or an error printed as is, because capture redaction covers secrets only. `capture.redact` takes `email` to keep addresses out of the store too. [Improve](https://github.com/jackulau/coding.sh/blob/main/docs/guides/improve.md#1-see-what-to-fix-first).
- **Storage.** An ingest or transcript import that stores more than 10,000 events empties the index's write-ahead log before it returns, and so does every command when it closes the index. Before, with the viewer or another command holding the index open, a full import left `index.db-wal` as large as the data it wrote (3.8 GB next to a 1.5 GB index) until a later command happened to close it last. [Architecture](https://github.com/jackulau/coding.sh/blob/main/docs/design/architecture.md#storage).
- **Proxy.** A model call that both `coding.sh proxy` and the agent's hooks or transcript logged shows once in `show`, `show --follow`, the viewer's timeline and the MCP `session_get` and `session_current` tools, as the proxy's copy with its call id, filled in with what only the other copy has. Before, each call printed twice, and MCP `latency` counted it twice. [Capture with the proxy](https://github.com/jackulau/coding.sh/blob/main/docs/how-to/capture-with-proxy.md#3-read-a-call).
- **Proxy.** Storing a call no longer slows down as the session grows. The proxy folds only the new events into the session row, instead of every event in the session, and writes the call's blobs in one batch. Late in a 1,000-call session a call now takes 9 ms to store instead of 26 ms. A call stored as message blocks reads back in about 2 ms instead of 9 ms. `bench.mjs proxy-session` measures the write against an older build. [Capture with the proxy](https://github.com/jackulau/coding.sh/blob/main/docs/how-to/capture-with-proxy.md#2-what-it-forwards).
- **Evals.** `exp show <id>` takes the experiment id that `eval run` prints for a tasks suite and lists its runs per task with the agent's cost at API prices. Before, it said the experiment was not found. [Evals](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#the-report).
- **Refine.** When a `refine run --suite` climb holds a cheaper or faster candidate whose quality is even on average but whose interval is too wide to confirm within `--margin`, the round now says the hold is a sample-size problem ("the quality interval is too wide to adopt it within the margin at N tasks: add tasks or trials") instead of implying the gain cost quality, and carries a warning that names the quality lower bound against the margin and the fix. The verdict is unchanged; only the explanation is clearer. [How good is the hill-climb, really?](https://github.com/jackulau/coding.sh/blob/main/docs/research/hillclimb-quality.md).
- **Cost.** `usage` `TOK/TURN` (`tokensPerTurn`) divides only top-level sessions' tokens by their turns. Before, subagents' tokens were divided by their parents' turns, so a row with heavy subagents, or a model only subagents ran, showed an inflated or impossible tokens per turn. [Expensive sessions](https://github.com/jackulau/coding.sh/blob/main/docs/how-to/expensive-sessions.md).

### Performance

- **Ingest.** The SQLite index gives each connection a 16 MB page cache (`cache_size`) and in-memory temp b-trees (`temp_store`), both bounded RAM freed on close, and ingest skips the duplicate `session_facets` inserts a session repeats across its events (the facet table is unchanged). Measured the paired way with `scripts/dogfood/bench.mjs ingest --baseline <dist>`. [Store ingest](https://github.com/jackulau/coding.sh/blob/main/docs/perf.md#store-ingest).

## [0.1.2] - 2026-11-08

coding.sh runs on Windows, and CI tests it there.

### Added

- **Sessions.** A new `text-tool-call` flag marks a session whose model wrote a tool call out as text, so the call never ran. In Claude Code this is usually a subagent whose `tools:` frontmatter is a map (`edit: false`), which leaves it with no tools; `improve` names the fix. [Concepts](https://github.com/jackulau/coding.sh/blob/main/docs/concepts.md#recording).
- **Sessions.** A session whose main thread moved to another model mid-session, such as Claude Code's silent fallback to an older model after a refusal, gets the `model:switch` tag and `stats.modelSwitch` with both models, when, and the trigger (`refusal`, `error` or `/model`). `stats.models` counts calls per model (both show in a Models row in `show` and the MCP digest), a refused call adds the `refusal` flag, and a session's model is now the one most of its main-thread calls ran on instead of the last one seen. Helper models (Haiku titles) and subagents are not a switch. [Read API](https://github.com/jackulau/coding.sh/blob/main/docs/reference/api.md#get-apisessionsid).
- **Evals.** `eval validate` takes several tasks, or `--tag <tag>` for every task with that tag (`suite:<name>` for a suite), prints one line per task and exits 1 if any did not validate. [Evals](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#session-to-eval).
- **Evals.** `eval init --sessions --repo <DIR|all>` drafts tasks from sessions in another checkout or worktree of the project, not only the current one. [Evals](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md).
- **Docs.** Use-case pages for tracking Claude Code and Codex cost, replaying a session, testing a CLAUDE.md, AGENTS.md or skill change, building evals from failures, self-hosting, and logging model calls through the proxy. Comparison pages for Langfuse, LangSmith, Braintrust, AgentOps, Laminar and ccusage, each with a feature table, where the other tool is the better choice, and its sources. [Compare](https://coding.sh/docs/compare).
- **Site.** Every docs page has its own link preview image, the home page and FAQ carry FAQ markup, and the site build fails on a missing or too-long title or description, a wrong canonical URL, or a link to a page that doesn't exist.
- **Evals.** `eval validate` checks verifiers that grade the agent's answer or trace: a task dir's `reference/` (`output.md`, `stdout.jsonl`) is a correct run that must pass, and `near-misses/<label>/` hold wrong runs that must fail. The verifier reads them through `CODING_SH_AGENT_OUTPUT`, `CODING_SH_AGENT_STDOUT` and `CODING_SH_AGENT_DIFF`, as in a real run. [Evals](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#hand-written-tasks).

When the candidate resumes from recorded runs (`resumeFromRunId`) and no baseline run resumes from the same ones, it notes "no control fork", since the difference would mix the edit with the replay itself. With a control, it reports how often the control's outcome changed from its source run as the replay noise floor (`control.drift` in `--json`). [Workflows guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#workflows).
- **Production.** `coding.sh-store-clickhouse` runs serve, the CLI and MCP on ClickHouse: `--store 'clickhouse://user:pass@host:8123/db'` (`clickhouses://` for TLS). It has no runtime dependencies and passes the store conformance suite; blobs stay on `file://` or S3. The same page shows how to send sessions to an OpenTelemetry Collector that writes to ClickHouse, with SQL for cost, slow tools and failed sessions. [Self-host for a team](https://github.com/jackulau/coding.sh/blob/main/docs/how-to/self-host-team.md#clickhouse).
- **Evals.** `eval validate` flags hidden tests that name a helper or file only the reference adds and the instruction never mentions, which fail valid fixes written differently (`--strict-coupling` makes it blocking). `eval crosscheck <task>` has a reviewer model judge stored runs' diffs against the instruction and lists the runs where it disagrees with the verifier, as false rejects or false accepts. `--solver <bundle>` solves the task once first. The counts are stored on the task in the same shape as a human verifier audit. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#session-to-eval)
- **Experiments.** Long runs survive interruptions. `exp run`, `exp aa`, `exp sweep`, `compare`, `bench run` and `workflows run` save each trial as it finishes, and `--resume [<id>]` re-runs only the unfinished ones, with the same seed, order and `--stop-early` decision as an uninterrupted run. A changed config refuses to resume and names what changed. The first Ctrl-C lets trials in flight finish. Rate limits, 5xx and network errors are retried with backoff (`--retries`, default 3), task failures never are. `--trial-timeout` caps a trial, and `exp status` shows progress, ETA and cost so far. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#long-runs-resume-retries-status).
- **Judges.** `follows-rules` reads rule-file frontmatter: a Claude Code rule with `paths:`, a Cursor rule with `globs:` (or neither glob nor `alwaysApply`), or a Copilot rule with `applyTo:` is graded only after the agent touches a matching file or opens the rule. Before that the agent never saw it, so it no longer counts as skipped. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#checklists-and-trace-checks)
- **Experiments.** `coding.sh exp ab` tests a CLAUDE.md, AGENTS.md, rule or skill edit on your own recent sessions, with no eval tasks to write. It finds the moments your agent went wrong (said done without running anything, stopped with tests failing, retried a failed command unchanged), replays the next turn there with your committed files and with your edit, and has a judge score both. It prints the fixed and broken cases, the same ship gate as `compare --gate`, and the replay noise floor from the control arm. `--dry-run` shows the cost first, `--max-cost` caps it, reruns are free from the cache, and `--watch` reruns on every save. CI runs it on real Claude Code sessions against a stub model. [Test a CLAUDE.md change in five minutes](https://coding.sh/docs/how-to/test-claude-md-change).
- **Experiments.** The pieces under `exp ab` work on their own: a `continuation` task replays a frozen session's next turn with given context files, and a decision-point miner turns sessions into a dataset of those moments, each with its own rubric. A continuation experiment needs a control arm: run it as an A/B, or pass `--no-control` and get a warning that there is no noise floor to read the difference against. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#ab-a-harness-edit-on-your-own-sessions).
- **Refine.** `coding.sh refine propose|test|apply|rollback|log|run` improves CLAUDE.md, AGENTS.md, rules and skills in tested rounds. `propose` asks a model for lines that address your sessions' most severe flags, with protected lines marked READ-ONLY. `test` checks a candidate before any model call (protected lines, harmful or duplicate added lines), A/Bs it against your current files on the decision points `exp ab` mines, and rejects it when it forgets what an earlier kept edit won (`guard: forgets kept edit r_…`). `apply` writes a kept edit with a backup, `rollback` restores it byte for byte, and `log` lists every round with its verdict, effect CI, guard result and reason. `run` loops until `--rounds`, `--max-cost` or the plateau detector says stop. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#refine-loop).
- **Refine.** `coding.sh refine score labels.jsonl --pred FILE` scores diagnoses against hand labels by code: occurrence, Signal and session precision, recall and F1, Signal coverage, recall per taxonomy family and, with 2+ `--pred` files, repeat agreement, each with its counts. Matching is maximum one-to-one on session, component and top-3 type ids. Without `--pred` it measures the precision of each session flag (Signals, arXiv 2611.04507). [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#scoring-diagnoses).
- **Refine.** `refine test|run --suite <name>` judges a harness edit on an eval suite of repo tasks, k trials per arm, and can make the harness cheaper and faster, not only better: `--objective cost,wall` keeps an edit whose pass rate holds within `--margin` (2pp by default) and whose cost, tokens, wall time, LLM time, turns or size drop significantly, and never keeps one that loses quality beyond the margin. With a cost or time objective the proposer cuts, shown what made the runs slow or expensive; `--proposer-command 'claude -p'` writes the edit with a command. `--until-plateau` climbs until the e-detector says it stopped gaining, `--resume` continues an interrupted round, a skill directory can be the `--target`, and `refine log` shows each climb's rounds and Pareto front. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#climbing-on-an-eval-suite).
- **Harness A/B.** `coding.sh refine check` exits 1 on a CLAUDE.md, AGENTS.md, rule or skill edit that deletes or rewords a protected safety line, or adds an exception that relaxes one (``protected-line: AGENTS.md:3 "Never run `git push --force`." (auto)``), since a pass-rate A/B can't see that harm (Masked Erosion, arXiv 2610.38392). A line is protected by a `<!-- coding.sh:protect -->` block, a `[refine] protect` regex, or automatically when one sentence pairs a gate word with a safety topic; `refine protected` lists them. `exp ab` runs the same check before any model call and fails `--gate` on it. `--allow-protected-edit AGENTS.md:3` allows one on purpose. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#protected-safety-lines).
- **Docs.** A Workflow experiments page: capture and score multi-agent runs, `workflows compare`, replays, the control fork and the replay noise floor. [Workflow experiments](https://coding.sh/docs/workflows)
- **Long sessions.** A session that runs for hours or days reads as one timeline split into phases: the start, each `claude --resume`, each compaction and each long idle gap. `show` lists the phases with day lines, `show --all` lists every event, and `show --follow` prints new events while a session runs. Derails mark where a run went off the rails: `looping`, `failure-streak`, `churn`, `no-progress`, `stalled` and `context-thrash`, each with the event and time it started. They show in `show`, on the viewer timeline (with ‹ › to step through them), in `sessions --flag <name>`, and in the MCP `sessions_list` and `session_get` tools. `compare` reports derails and time to first derail per run, and a `progress` grader scores time on track for `exp compare`. The viewer loads a 40,000-event session in the background and scrolls it smoothly, and MCP `session_get` with `tail` reads a long session's latest events. Live hook ingest updates a long session from its new events only: 0.46 s per update on a 30,000-event session, down from 1.16 s. [Long sessions](https://github.com/jackulau/coding.sh/blob/main/docs/guides/explore.md#long-sessions).
- **Experiments.** `exp compare --margin 0.03` checks that B is at most 3pp worse than A (paired non-inferiority on the 95% interval's lower bound) and exits 1 otherwise: `non-inf B − A ≥ -3.0pp: yes (95% CI lower bound -1.2pp > -3.0pp)`. It lists cases A passed on every trial that B now mostly fails. [Experiments](https://coding.sh/docs/experiments#non-inferiority).
- **Tool evals.** A `calls` check: tools the trial must call (`must`), must not call (`mustNot`), at most `max` calls, and an `order`, with partial argument matches (`~text` substrings, `<=N` bounds, dotted paths). It reads the trial's tap; the MCP tap now keeps each call's arguments, redacted. `exp run` takes the same fields as a `calls` grader over the task's trace. [Tool evals](https://github.com/jackulau/coding.sh/blob/main/docs/TOOL-EVALS.md#3-task-format).
- **Experiments.** `exp run` and `toolevals run` take `--samples adaptive`: 2 trials per case, a 3rd when they disagree, and a case fails at half or more failing; the report gives case verdicts and no CI. `--stop-on-regression --baseline <experiment>` stops the run and exits 1 once a case that passed every baseline trial fails. [Gating runs](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#gating-runs-tie-breaks-and-the-regression-stop).
- **Tool evals.** `toolevals compare` prints `p (perm)` beside McNemar: a task-paired permutation test on the per-task differences, exact over all sign flips up to 20 tasks and seeded Monte Carlo above. It holds its level at the 5-11 tasks a suite often has, where bootstrap intervals are too narrow (AT-AT, arXiv 2610.34679). `--json` carries `report.permutation`; verdicts are unchanged. [Tool evals](https://coding.sh/docs/tool-evals#experiments).
- **Judges.** `judge calibrate` prints the judge's discrimination gap and label efficiency η, and warns when auditing outputs directly would need fewer human labels: `label efficiency η 0.21 · auditing outputs directly needs ~4.8x fewer human labels for the same precision`. `--judge-cost 0.001` adds the human label cost above which the judge pays off. The calibration state is unchanged; `--json` carries `calibration.efficiency` (Choi et al., arXiv 2610.35698). [Evals](https://coding.sh/docs/evals#calibration).
- **Judges.** `exp compare --pairwise` and judge graders in `exp compare` print how often a resample of the cases picks the same winner, and n*, the smallest size where that holds 95% of the time: `stable  B better in 97% of resamples (n*=50)` or `unstable  B better in 61% of resamples (n* censored)`. An uncalibrated judge that never settles warns "pick or calibrate the judge before collecting more verdicts" (arXiv 2611.04090). `--json` carries `stability`. [Evals](https://coding.sh/docs/evals#judges).
- **Judges.** `judge sample <exp> --budget 60 --out plan.json` says which cases to label next: a seeded random sample stratified by the judge's verdict and confidence, with labels in proportion to stratum size, so the labels don't favour the doubtful cases. `judge calibrate --plan plan.json` then prints the human-audited pass rate: `human-audited pass rate 0.71 [0.63, 0.79] (42/50 of plan labelled; worst case ±0.09)` (Choi et al., arXiv 2610.35698). [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#which-cases-to-label).
- **Site.** Pages are ready about 0.5 s sooner on a slow phone, with half the font bytes and less layout shift. A Lighthouse A/B with budgets runs on every site change. [Site speed](https://coding.sh/docs/perf).
- **Site.** A blog at /blog: posts are Markdown files in `apps/site/src/content/blog`, each with its own page, title card and sitemap entry, and an Atom feed at /blog.xml. The first post explains why coding.sh keeps your sessions on your machine. [Blog](https://coding.sh/blog).
- **Capture.** Claude Code Bash commands that edit files (`sed -i`, a heredoc write, `tee`) record a `file.change` per file with its diff, taken from Claude Code's own edit diff, even when the command then failed. A nested CLAUDE.md or skills folder loaded mid-session, a Skill call's skill folder and the skills restored after `/compact` become `harness.loaded` events and show in `show` and the viewer timeline. Stored Claude Code sessions are re-parsed to pick them up. CI checks both on a real Claude Code 2.1.319 session. [Adapters](https://github.com/jackulau/coding.sh/blob/main/docs/ADAPTERS.md#known-breakage-to-design-around).
- **Sessions.** Each skill a session used, through the Skill tool or by reading or running a file in its folder, adds a `skill:<name>` tag, so `sessions --flag skill:pdf` finds those sessions. `show` lists them as `Skills  pdf (project, invoked, first, before any edit) · pdf-tools (personal, read)`, and `show --json` and MCP `session_get` return `skills`. A new `skill-copy-conflict` flag marks a session that used two copies of one skill (arXiv 2610.11647). [Concepts](https://github.com/jackulau/coding.sh/blob/main/docs/concepts.md).
- **Cost.** Two kinds of waste per session. Re-fetches are read-only calls (Read, Grep, `cat`, `git diff`, …) that returned the same result as an earlier call in the same context; three or more add the `duplicate-fetch` flag (arXiv 2611.07238). Cache breaks are model calls that found the prompt cache gone and paid for the prompt again, by cause (compaction, model switch, idle, other), priced as cache write minus cache read (arXiv 2610.35496). `show` prints `Cache breaks  2: 31k prompt tokens billed again, $0.1086 extra (other 1, compaction 1)`, `usage` totals both per group, and the viewer header, `--json` and MCP carry `stats.waste` and `stats.cacheBreaks`. [API reference](https://github.com/jackulau/coding.sh/blob/main/docs/reference/api.md).
- **Sessions.** New `test-tamper` flag: the agent added a skip marker to a test, deleted a test file while tests failed, or changed an assertion and that edit alone turned a failing run green. It reads Edit/Write/apply_patch changes and shell writes (`sed -i`, `>`, `tee`, `rm`, `mv`, `git checkout`), and covers test-runner configs and CI files. New tests and files the agent created itself are not flagged. On 3,957 local sessions it flags 13 (EPISTEME, arXiv 2611.06563). [Concepts](https://github.com/jackulau/coding.sh/blob/main/docs/concepts.md).
- **Harness A/B.** `compare` links each tamper flag to the tool call that made the change and splits tampered passes by whether the agent said it was changing the test: `tampered passes  B 3: disclosed 2, stealth 1`, then one line per pass with the run, file, tool, event id and the agent's words. `--json` adds `tamperAttribution` per run, and the MCP `harness_compare` tool a `tamper` field. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#harness-ab).
- **Judges.** New `no-test-tamper` checklist check, with no model call: it answers no when a test change hid a failure (a skip marker, a test deleted while red, an assertion edit that alone turned the tests green), cites the change and the test runs around it, and quotes what the agent said: `weaken test/sum.test.js by Edit in e42 (turned failing tests green), disclosed: "…"`. Saying why never makes it pass. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#checklists-and-trace-checks).
- **Evals.** `eval audit <task> --experiment <id> --witness <file> --witness-cmd <cmd>` replays a witness test, one that checks a requirement the verifier skips, on every passing run: `claude-tdd: passes 6/10, refuted 3, audited pass rate 30% (3/10)`. The witness must pass the reference 3/3 first. A replay whose verifier no longer passes is `replay-mismatch`, never refuted, and a witness refuting over half the passes is ambiguous and not counted. No model calls (TestJack, arXiv 2610.10619). `--promote` adds it to the verifier, and `eval export`/`import` carry witnesses. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#witness-audits).
- **Harness A/B.** After `eval audit`, `compare` shows each audited arm's raw and audited pass rate, `audited pass  B 60% → 30% (3 refuted, coverage 100%)`. `--audited` counts refuted passes as fails and labels the verdict `verdict (audited)`, with a note when the audit changes it. It needs every pass in both arms replayed, or the raw verdict stands with a coverage note. `--json` and the MCP `harness_compare` tool add the per-arm counts. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#harness-ab).
- **Harness A/B.** `compare` adds a `surface` row: the bytes of instruction text each bundle puts in front of the agent (CLAUDE.md, AGENTS.md, GEMINI.md, skills, rules, system-prompt files, `~/` ones too). When B's is more than 20% bigger, a note asks for a success CI above 0 rather than a tie, since those bytes cost tokens on every turn. `--json` has the sizes per file in `report.surface`. [Compare agents](https://github.com/jackulau/coding.sh/blob/main/docs/how-to/compare-agents.md#why-runs-failed).
- **Evals.** Experiment sessions: `exp session new --name <topic>` starts one in a folder, and each `exp run` there prints its delta against the previous run on the same dataset as it finishes (`pass 0.0% → 100.0%  Δ +100.0pp […]  mcnemar p=0.125`, the grader deltas, the cases fixed and broken, the files changed), with no `exp compare`. `exp session note` records hypotheses and readings, `exp session summary [--json]` prints the timeline. `exp run --watch` reruns on every save of the spec, the agent script, grader files or `watch` globs, aborts a run made stale mid-way without storing it, and regrades the stored outputs with 0 agent calls when only the graders changed. [Evals](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#sessions-deltas-notes-watch).
- **MCP.** `exp_session_note` adds a redacted note to the project's experiment session (the hypothesis before a run, the reading after it) and `exp_session_summary` returns its timeline, paged, with the same blocks as `exp session summary --json`, so an agent can pick an investigation back up after a context reset. Without a session both return a `not_found` error naming `coding.sh exp session new --name <topic>`. [Explore](https://github.com/jackulau/coding.sh/blob/main/docs/guides/explore.md#mcp).
- **Experiments.** `exp regrade <experiment> spec.json` grades a stored experiment's outputs again with new graders, without calling the task, and prints the pass rate before and after, each grader's version change and every run that flipped (`flips 1 of 4 runs: 1 pass → fail`). `exp compare` pins grader versions: a grader that changed version or graded one side only gets a warning above the verdict, and cases left ungraded on one side are listed. [Evals](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#regrade).
- **Experiments.** `exp run matrix.json` runs a spec with `"matrix"` (JSON Pointer axes, every combination) or `"variants"` (named cells plus `"vary"`) against a baseline cell: the cells run interleaved, each is stored as its own experiment with `metadata.matrix`, each is compared with the baseline, and the McNemar p-values are Holm-adjusted over the cells. A cell that differs from the baseline outside `vary`, or touches graders or the dataset, is refused before any call; `--plan` prints the cells and runs nothing, `--cell` runs a subset, `--resume` continues an interrupted matrix. [Evals](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#matrix).
- **Graders.** The `agent-slop` grader flags placeholder code, `as any` and `@ts-ignore`, empty catches, leftover debugging, focused or skipped tests and narrating comments in the lines an agent's diff adds, and `coding.sh judge slop <session|run|experiment>` scores captured work with it, per arm for a compare experiment. - **Query.** `coding.sh sql "select …"` runs one read-only SQL query against the SQLite index: one `SELECT` or `WITH` statement on a read-only connection with `query_only` on, with a timeout (`--timeout`, 10 s) and a row cap (`--limit`, 1000). Writes, `ATTACH`, `PRAGMA` and a second statement exit 2; Postgres and ClickHouse stores get an error that points to `export`. `coding.sh export sessions|events|labels` streams rows as JSONL or CSV with the same filters as `sessions`, on every store. - **Experiments.** `compare A B --reuse baseline` copies A's finished runs from earlier comparisons instead of running them again (`--reuse both` copies B's too), so several candidates against one baseline pay for it once. - **Evals.** An `executability` grader scores a run by how far it got before its first invalid tool call, one the harness refused to run (a bad argument, an unknown tool, an edit of a file not read yet, a string to replace that is not there, a missing file or command, a denied call). A test that exits 1 ran and is not invalid. The score is the share of steps before that call (its mean is AUC-PEC), and it passes with at most `maxInvalid` invalid calls (its pass rate is TER); `kinds` counts only some kinds (Prefix Executability, arXiv 2610.40444). [Explore guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/explore.md#executability).
- **Query.** `sessions`, `search`, `usage` and `export` take `--where`, one filter language over any session or event field: `agent:codex cost>0.5 tool:Bash ok:false -flag:compaction`, with `OR`, `( )`, wildcards, ranges, `sort:` and `limit:`. `sessions --facets model,tool` counts sessions per value. The viewer API (`?where=`, `/api/facets`) and the MCP tools `sessions_list`, `search` and `usage` (`where`, `facets`) take the same queries. On SQLite a query is one parameterized SQL statement; a typo is a usage error that points at the character. [Query and export](https://github.com/jackulau/coding.sh/blob/main/docs/reference/query.md#filter-with---where)
- **Query.** `--where` on tools, MCP servers, event kinds and `ok` reads indexes instead of scanning events, and their facet counts come from a small per-session table. The store migrates once on open (about a minute at that size, +4% on disk). `GET /api/events` returns matching events across sessions, newest first and keyset-paged, and `/api/facets` takes `prefix` for autocomplete. ## [0.1.0] - 2026-11-06

The first public release, still pre-1.0. coding.sh records what your AI agents do, with coding
agents first-class, on your own machine, shows it in a local viewer, and turns those sessions into evals and A/B experiments.
It also runs as a server on SQLite or Postgres, with SDKs for apps that call model APIs.

### Added
