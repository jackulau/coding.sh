# Changelog

All notable changes to coding.sh are listed here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions will
follow [Semantic Versioning](https://semver.org/) from the first npm release.

Each release opens with a short summary. The list under it has one line per change,
grouped by area, with links to the docs for the details.

## [0.1.2] - Unreleased

coding.sh runs on Windows, and CI tests it there.

### Added

- **Stores.** The Postgres and ClickHouse store plugins answer `--where` in the database, with every value bound: session and event keys, `has:`, `is:`, bare words, `sort:` and `--facets`, for `sessions`, `usage`, `export`, the viewer API and MCP. `sessions --where` and facets no longer stop at the newest 20,000 sessions there, and event keys and bare words no longer fail with `unsupported_store`. [Query language](https://github.com/jackulau/coding.sh/blob/main/docs/reference/query.md).
- **Harness A/B.** `compare --repair N` reports Seq@1..N+1 per arm: the share of tasks solved by the k-th attempt with verifier feedback, with intervals, where the gain lands (EGS, LGS), rounds that changed no file, and the agent's spend per solved run. With `--k 2` or more it adds a cost front of k attempts with feedback against k independent attempts (unbiased pass@k), and a note when the two arms rank one way on the first attempt and the other way after the rounds (Seq@K, arXiv 2610.37859). [Evals](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#repair-rounds).
- **Harness A/B.** `compare --repair N` tells the agent "Verification failed." in its own session (Claude Code `--resume`, `codex exec resume`) after a failed verifier, up to N rounds, with the hidden tests out of its tree. The report adds the repair rate, mean rounds and the rounds' cost per arm. `--repair-signal names` adds the failing test names from the verifier output; a round that edits, deletes or skips tests is not a repair; `--false-alarm P` tells a seeded share of passing runs they failed; `--repair-verdict` decides on the outcome after repair. Repair settings are part of the `--reuse` key (BOBA, arXiv 2611.02207). [Evals](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#repair-rounds).
- **Skills.** `eval trigger <skill-dir>` checks that the agent loads a skill when it should and not when it shouldn't. It runs the `should` and `should_not` prompts in `triggers.toml` k times each with the skill and its siblings installed, reads each load from the captured session, and reports precision, recall and F1 with Wilson intervals, the missed and flaky prompts, and near misses that went to the expected sibling. `--description` or `--candidate` A/Bs a new description with a paired bootstrap CI and the prompts that flipped. `--min-f1` and `--fail-on regression` set the exit code. CI checks it with real Claude Code and Codex against a stub model. [Evaluate an Agent Skill](https://coding.sh/docs/how-to/evaluate-a-skill#does-the-skill-load).
- **Self-host.** `docker run -p 4318:4318 -v coding-sh:/data ghcr.io/jackulau/coding.sh` starts a team server with no configuration: with no keys set, the first start makes a read key and an ingest key, keeps them in the volume and prints them with the connect command. Each tagged release publishes the image for amd64 and arm64, starting with this one. `deploy/compose/` has SQLite, Postgres and ClickHouse stacks that need no edits. The viewer's sign-in page takes the read key in a form. serve waits up to 30 s for its database to accept connections. [Self-host for a team](https://coding.sh/docs/how-to/self-host-team).
- **Self-host.** `coding.sh init --remote <url> --key csh_ik_…` connects a machine to a team server in one command: it checks the key, installs capture hooks and adds the `team` sink. `--remote-mode full` also sends prompts and output. [Self-host for a team](https://coding.sh/docs/how-to/self-host-team#connect).
- **Install.** Windows: run the installer from Git Bash. Hook commands use `C:/…` paths that cmd.exe, PowerShell and Git Bash all run. CI runs the tests and the installer on Windows. [Install guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/install.md#windows).
- **Capture.** CI runs real OpenCode, Pi, Goose, Factory Droid, GitHub Copilot CLI and Aider sessions on Linux and Windows against a stub model, checks the recorded prompt, tool call, file change, model and reply, and checks that `ingest --backfill` adds no duplicates. [Install guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/install.md#windows).
- **Gateways.** OpenRouter, LiteLLM, Cloudflare AI Gateway, Portkey, Helicone and Ramp Router (router.com) join Vercel: sessions get a `gateway:<name>` tag, `gateway enrich` fetches billed cost where the gateway has a lookup API, `gateway status` shows one row per gateway, and `compare --gateway <name>` routes runs through it. [AI gateways](https://coding.sh/docs/ai-gateway).
- **SDKs.** The TypeScript and Python SDKs detect all twelve gateways, not only Vercel: by base URL, a self-hosted gateway's URL env var, a response header (`cf-aig-log-id`, `helicone-id`, `x-litellm-call-id`, `x-portkey-trace-id`, …) or the response id. Each model call records the gateway and its request id, so SDK sessions get the `gateway:<name>` tag and `gateway enrich` can fetch their billed cost. The SDK tables are generated from the server's gateway list. [AI gateways](https://coding.sh/docs/ai-gateway#sdk).
- **Experiments.** `compare` records the agent release each run started on (`agentVersion`, checked at most once a minute, so an auto-update mid-run shows). When the arms ran on different releases, the report adds `agent claude-code 2.1.316 ×12  2.1.319 ×12  release differs` and a note that the delta mixes the change with the release, `--gate` repeats it, and `--promote` holds with `release_confound`. `--json` carries `report.agentVersions` (arXiv 2610.37332). [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#agent-release).
- **Experiments.** `exp compare` and `compare` give the exact McNemar power next to the normal MDE: `power   MDE 15.6pp · no 80% power at this n (exact McNemar ceiling 62%)` or `· exact MDE 10.6pp`. The exact test needs 6 flipped cases to reject at α 0.05, so a small suite can have no 80% power for any gap; a `no-power` warning says so, and `--json` carries `power.exact` (arXiv 2610.04433). [Evals](https://coding.sh/docs/evals#compare).
- **Experiments.** `exp run --series NAME` tags each round of an iteration loop and prints whether to stop. `exp plateau` runs a restart e-detector over the series and names the version to ship. It exits 3 to stop, 0 to continue and 2 with too few experiments (Yin et al., arXiv 2610.04756). [Evals](https://coding.sh/docs/evals#plateau).
- **Experiments.** `exp metrics` A/Bs two commands that print numbers (ms, bytes) in interleaved pairs, with a 95% paired bootstrap CI and a sign test per metric. `--fail-on-worse` exits 1 for CI. [Evals](https://coding.sh/docs/evals#metrics).
- **Capture.** Sessions stored before an adapter's parsing changed are re-parsed from their transcripts and spool in the background, so this release's dedupe fixes reach data already captured. `coding.sh ingest --rebuild` does it now. [Troubleshooting](https://github.com/jackulau/coding.sh/blob/main/docs/troubleshooting.md#old-sessions-show-doubled-counts).
- **Harness A/B.** `compare --gate` answers "ship B or not": `Ship it: B wins 9 tasks, loses 0`, `Hold: not enough evidence`, or `Don't ship: B breaks 3 tasks A solved` with the broken tasks listed. It exits 0 only for "Ship it" (SAGE, arXiv 2609.36043). `--by suite:` gates each tagged suite too, and one broken suite blocks a pooled "Ship it". Each arm's failed runs are split by the agent's own last test run: `A fails 12: own tests green 7 (58%), red 3, stale 1, none 1`, where green fails are silent misses (BOBA, arXiv 2611.02207). `compare --promote` also keeps a B that is cheaper at the same quality: `pareto: support 0.93 ≥ 0.70 → promote (cost-cut: …)` or `→ hold`, exit 0 only on promote (ParetoSaddler, arXiv 2611.02079). When B adds or removes one rule, skill or context file, the report adds a one-item gate scored only on tasks where the item reached the agent's context: `item gate k=3 τ=.34 m=2: KEEP · …`, or RECHECK, KILL, RERUN, and ACCEPT, REJECT, UNMEASURED for removals; `--item-gate` sets the exit code (Cortex, arXiv 2610.14216). CI checks the gate and the own-tests split on real Claude Code and Codex sessions against a stub model. The MCP `harness_compare` tool lists these A/B results and returns one with its gates and own-tests split. [Compare agents](https://github.com/jackulau/coding.sh/blob/main/docs/how-to/compare-agents.md#ship-it-or-not).
- **Experiments.** `exp compare --gate` gives the same ship-or-hold answer per case and exits 1 unless it is "Ship it". `exp sweep` ends with `adopt <winner>` or `keep <start>` and the reason. The MCP `experiment_compare` tool returns the gate too. With 2+ trials, `exp compare` also lists the cases B gained and lost (passed in any trial), counts cases that got more or less reliable, and warns when the two halves of the trials disagree; `--matrix` prints the success counts (EvoAudit, arXiv 2611.07624). [Evals](https://coding.sh/docs/evals#compare).
- **Durable workflows.** A Vercel Workflow, Temporal, Inngest, Restate, DBOS, LangGraph or Cloudflare Workflows run (Temporal, Restate and DBOS in both TypeScript and Python) is one session across processes, traces, crashes and deploys (keyed by run id). `show`, `workflows show` and the viewer list each step with its attempts, failed and lost ones included, show sleeps and LangGraph interrupts as waiting rather than work, mark where the run resumed after a crash, deploy or restart, and leave replayed model calls out of tokens. An attempt lost with its process counts as busy only while its process was still seen; `workflows stats` shows the rest as "lost to crashes" instead of agent time. A span with `workflow.wait.name` around a sleep is a wait in any engine, for those that export none (Temporal, Inngest, DBOS TS). New flags `step-retried` and `resumed`. Each engine is checked in CI against a real run with a failed step, a killed worker, a sleep and a restart. [Trace a durable workflow](https://coding.sh/docs/how-to/trace-durable-workflow).
- **Evals.** Behaviour tasks can be written by hand and loaded with `eval import tasks/*/`; `compare --tag <tag>` runs them. Verifiers get the agent's final answer and full stdout (`CODING_SH_AGENT_OUTPUT`, `CODING_SH_AGENT_STDOUT`), and `judge grade --grader checklist.json` grades both from inside one. `compare` reports `agent spend` and `grader spend` rows, `--max-cost 15` stops starting runs at $15, per-task rows show task names, and a fresh store gets its hook script so runs are captured. [Evaluate an Agent Skill](https://coding.sh/docs/how-to/evaluate-a-skill).
- **Viewer.** Cost shows in the session list, the session header and on each model call. Estimates read `~$0.04` (hover: "Estimated from list prices", and which price a call used); billed and reported costs have no mark; a call with no price shows `—` and says why.
- **Judges.** Judge prompts escape data tags in the judged text and say it is untrusted, so an output can't close `</output>` and order a pass. `judge calibrate --probe-injection judge.json` plants a "respond pass" order in human-fail cases and reports how many verdicts flip; any flip exits 1. Default-prompt judges get new version ids. [Evals](https://coding.sh/docs/evals#calibration).
- **Judges.** Checklist items can grade rule compliance from the trace with no model call: `ran-command`, `read-path`, `wrote-identifier`, and `follows-rules`, which checks every imperative line that names a backticked command, flag, path or identifier (``Never use `git push --force` ``) against what the agent did. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#checklists-and-trace-checks).
- **Cost.** Estimates price each model call at the rates it ran at: long-context rates past the model's threshold (OpenAI over 272K, Gemini Pro and Claude Sonnet 4.5 1M over 200K, Haiku 5.5 over 100K), and batch, flex, priority, fast or Claude fast-mode rates from the call's recorded service tier. The call's `payload.priceTier` says which, and shows in `show` and the viewer's cost tooltip. `usage --json` adds `estimatedCostByTier`. `[prices]` takes `long_context` and tier tables. Claude 1-hour cache writes are priced at 2x input instead of 1.25x, from Claude Code's `cache_creation.ephemeral_1h_input_tokens` and OpenTelemetry `cache_creation_1h_tokens`, and Claude 4.6+ calls with `inference_geo: "us"` at 1.1x (`[prices]` takes `cache_write_1h` and a `geo` table). Stored estimates reprice by themselves. [Where cost comes from](https://github.com/jackulau/coding.sh/blob/main/docs/how-to/expensive-sessions.md#where-cost-comes-from).
- **Judges.** `judge calibrate --grader tests` audits a test or command verifier: `--sample-passes 40` lists unlabelled passing cases to label, and the audit reports precision (how many passes a person would accept) with a Wilson interval and the false accepts. `exp show` and `exp compare` then print the precision and a pass rate corrected for it. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#auditing-a-test-verifier).
- **Workflows.** `workflows compare` gives each variant P(front), the share of bootstrap draws in which no other variant beats it on quality and cost (`front 0.93`, `dominated by base (front 0.41)`). Near-equal noisy variants no longer get a confident "dominated". `--select min-cost --q-drop 10`, `--select weighted --lambda 2` or `--select pareto` picks a variant to deploy and prints `deploy: cand (…)` with the reason. `--seed` fixes the bootstrap (ParetoSaddler, arXiv 2611.02079). [Workflows guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/workflows.md#pick-a-variant-to-deploy)
- **Workflows.** `workflows compare` checks replay experiments for a control fork. When the candidate resumes from recorded runs (`resumeFromRunId`) and no baseline run resumes from the same ones, it notes "no control fork", since the difference would mix the edit with the replay itself. With a control, it reports how often the control's outcome changed from its source run as the replay noise floor (`control.drift` in `--json`). [Workflows guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#workflows).
- **Production.** `coding.sh-store-clickhouse` runs serve, the CLI and MCP on ClickHouse: `--store 'clickhouse://user:pass@host:8123/db'` (`clickhouses://` for TLS). It has no runtime dependencies and passes the store conformance suite; blobs stay on `file://` or S3. The same page shows how to send sessions to an OpenTelemetry Collector that writes to ClickHouse, with SQL for cost, slow tools and failed sessions. [Self-host for a team](https://github.com/jackulau/coding.sh/blob/main/docs/how-to/self-host-team.md#clickhouse).
- **Evals.** `eval validate` flags hidden tests that name a helper or file only the reference adds and the instruction never mentions, which fail valid fixes written differently (`--strict-coupling` makes it blocking). `eval crosscheck <task>` has a reviewer model judge stored runs' diffs against the instruction and lists the runs where it disagrees with the verifier, as false rejects or false accepts. `--solver <bundle>` solves the task once first. The counts are stored on the task in the same shape as a human verifier audit. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#session-to-eval)
- **Experiments.** Long runs survive interruptions. `exp run`, `exp aa`, `exp sweep`, `compare`, `bench run` and `workflows run` save each trial as it finishes, and `--resume [<id>]` re-runs only the unfinished ones, with the same seed, order and `--stop-early` decision as an uninterrupted run. A changed config refuses to resume and names what changed. The first Ctrl-C lets trials in flight finish. Rate limits, 5xx and network errors are retried with backoff (`--retries`, default 3), task failures never are. `--trial-timeout` caps a trial, and `exp status` shows progress, ETA and cost so far. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#long-runs-resume-retries-status).
- **Judges.** `follows-rules` reads rule-file frontmatter: a Claude Code rule with `paths:`, a Cursor rule with `globs:` (or neither glob nor `alwaysApply`), or a Copilot rule with `applyTo:` is graded only after the agent touches a matching file or opens the rule. Before that the agent never saw it, so it no longer counts as skipped. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#checklists-and-trace-checks)
- **Experiments.** `coding.sh exp ab` tests a CLAUDE.md, AGENTS.md, rule or skill edit on your own recent sessions, with no eval tasks to write. It finds the moments your agent went wrong (said done without running anything, stopped with tests failing, retried a failed command unchanged), replays the next turn there with your committed files and with your edit, and has a judge score both. It prints the fixed and broken cases, the same ship gate as `compare --gate`, and the replay noise floor from the control arm. `--dry-run` shows the cost first, `--max-cost` caps it, reruns are free from the cache, and `--watch` reruns on every save. CI runs it on real Claude Code sessions against a stub model. [Test a CLAUDE.md change in five minutes](https://coding.sh/docs/how-to/test-claude-md-change).
- **Experiments.** The pieces under `exp ab` work on their own: a `continuation` task replays a frozen session's next turn with given context files, and a decision-point miner turns sessions into a dataset of those moments, each with its own rubric. A continuation experiment needs a control arm: run it as an A/B, or pass `--no-control` and get a warning that there is no noise floor to read the difference against. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#ab-a-harness-edit-on-your-own-sessions).
- **Refine.** `coding.sh refine propose|test|apply|rollback|log|run` improves CLAUDE.md, AGENTS.md, rules and skills in tested rounds. `propose` asks a model for lines that address your sessions' most severe flags, with protected lines marked READ-ONLY. `test` checks a candidate before any model call (protected lines, harmful or duplicate added lines), A/Bs it against your current files on the decision points `exp ab` mines, and rejects it when it forgets what an earlier kept edit won (`guard: forgets kept edit r_…`). `apply` writes a kept edit with a backup, `rollback` restores it byte for byte, and `log` lists every round with its verdict, effect CI, guard result and reason. `run` loops until `--rounds`, `--max-cost` or the plateau detector says stop. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#refine-loop).
- **Refine.** `coding.sh refine score labels.jsonl --pred FILE` scores diagnoses against hand labels by code: occurrence, Signal and session precision, recall and F1, Signal coverage, recall per taxonomy family and, with 2+ `--pred` files, repeat agreement, each with its counts. Matching is maximum one-to-one on session, component and top-3 type ids. Without `--pred` it measures the precision of each session flag (Signals, arXiv 2611.04507). [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#scoring-diagnoses).
- **Harness A/B.** `coding.sh refine check` exits 1 on a CLAUDE.md, AGENTS.md, rule or skill edit that deletes or rewords a protected safety line, or adds an exception that relaxes one (``protected-line: AGENTS.md:3 "Never run `git push --force`." (auto)``), since a pass-rate A/B can't see that harm (Masked Erosion, arXiv 2610.38392). A line is protected by a `<!-- coding.sh:protect -->` block, a `[refine] protect` regex, or automatically when one sentence pairs a gate word with a safety topic; `refine protected` lists them. `exp ab` runs the same check before any model call and fails `--gate` on it. `--allow-protected-edit AGENTS.md:3` allows one on purpose. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#protected-safety-lines).
- **Docs.** A Workflow experiments page: capture and score multi-agent runs, `workflows compare`, replays, the control fork and the replay noise floor. [Workflow experiments](https://coding.sh/docs/workflows)
- **Long sessions.** A session that runs for hours or days reads as one timeline split into phases: the start, each `claude --resume`, each compaction and each long idle gap. `show` lists the phases with day lines, `show --all` lists every event, and `show --follow` prints new events while a session runs. Derails mark where a run went off the rails: `looping`, `failure-streak`, `churn`, `no-progress`, `stalled` and `context-thrash`, each with the event and time it started. They show in `show`, on the viewer timeline (with ‹ › to step through them), in `sessions --flag <name>`, and in the MCP `sessions_list` and `session_get` tools. `compare` reports derails and time to first derail per run, and a `progress` grader scores time on track for `exp compare`. The viewer loads a 40,000-event session in the background and scrolls it smoothly, and MCP `session_get` with `tail` reads a long session's latest events. Live hook ingest updates a long session from its new events only: 0.46 s per update on a 30,000-event session, down from 1.16 s. [Long sessions](https://github.com/jackulau/coding.sh/blob/main/docs/guides/explore.md#long-sessions).
- **Experiments.** `exp compare --margin 0.03` checks that B is at most 3pp worse than A (paired non-inferiority on the 95% interval's lower bound) and exits 1 otherwise: `non-inf B − A ≥ -3.0pp: yes (95% CI lower bound -1.2pp > -3.0pp)`. It lists cases A passed on every trial that B now mostly fails. [Evals](https://coding.sh/docs/evals#non-inferiority).
- **Tool evals.** `toolevals compare` prints `p (perm)` beside McNemar: a task-paired permutation test on the per-task differences, exact over all sign flips up to 20 tasks and seeded Monte Carlo above. It holds its level at the 5-11 tasks a suite often has, where bootstrap intervals are too narrow (AT-AT, arXiv 2610.34679). `--json` carries `report.permutation`; verdicts are unchanged. [Tool evals](https://coding.sh/docs/tool-evals#experiments).
- **Judges.** `judge calibrate` prints the judge's discrimination gap and label efficiency η, and warns when auditing outputs directly would need fewer human labels: `label efficiency η 0.21 · auditing outputs directly needs ~4.8x fewer human labels for the same precision`. `--judge-cost 0.001` adds the human label cost above which the judge pays off. The calibration state is unchanged; `--json` carries `calibration.efficiency` (Choi et al., arXiv 2610.35698). [Evals](https://coding.sh/docs/evals#calibration).
- **Judges.** `exp compare --pairwise` and judge graders in `exp compare` print how often a resample of the cases picks the same winner, and n*, the smallest size where that holds 95% of the time: `stable  B better in 97% of resamples (n*=50)` or `unstable  B better in 61% of resamples (n* censored)`. An uncalibrated judge that never settles warns "pick or calibrate the judge before collecting more verdicts" (arXiv 2611.04090). `--json` carries `stability`. [Evals](https://coding.sh/docs/evals#judges).
- **Judges.** `judge sample <exp> --budget 60 --out plan.json` says which cases to label next: a seeded random sample stratified by the judge's verdict and confidence, with labels in proportion to stratum size, so the labels don't favour the doubtful cases. `judge calibrate --plan plan.json` then prints the human-audited pass rate: `human-audited pass rate 0.71 [0.63, 0.79] (42/50 of plan labelled; worst case ±0.09)` (Choi et al., arXiv 2610.35698). [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#which-cases-to-label).
- **Site.** Pages are ready about 0.5 s sooner on a slow phone, with half the font bytes and less layout shift. A Lighthouse A/B with budgets runs on every site change. [Site speed](https://coding.sh/docs/perf).
- **Capture.** Claude Code Bash commands that edit files (`sed -i`, a heredoc write, `tee`) record a `file.change` per file with its diff, taken from Claude Code's own edit diff, even when the command then failed. A nested CLAUDE.md or skills folder loaded mid-session, a Skill call's skill folder and the skills restored after `/compact` become `harness.loaded` events and show in `show` and the viewer timeline. Stored Claude Code sessions are re-parsed to pick them up. CI checks both on a real Claude Code 2.1.319 session. [Adapters](https://github.com/jackulau/coding.sh/blob/main/docs/ADAPTERS.md#known-breakage-to-design-around).
- **Sessions.** Each skill a session used, through the Skill tool or by reading or running a file in its folder, adds a `skill:<name>` tag, so `sessions --flag skill:pdf` finds those sessions. `show` lists them as `Skills  pdf (project, invoked, first, before any edit) · pdf-tools (personal, read)`, and `show --json` and MCP `session_get` return `skills`. A new `skill-copy-conflict` flag marks a session that used two copies of one skill (arXiv 2610.11647). [Concepts](https://github.com/jackulau/coding.sh/blob/main/docs/concepts.md).
- **Cost.** Two kinds of waste per session. Re-fetches are read-only calls (Read, Grep, `cat`, `git diff`, …) that returned the same result as an earlier call in the same context; three or more add the `duplicate-fetch` flag (arXiv 2611.07238). Cache breaks are model calls that found the prompt cache gone and paid for the prompt again, by cause (compaction, model switch, idle, other), priced as cache write minus cache read (arXiv 2610.35496). `show` prints `Cache breaks  2: 31k prompt tokens billed again, $0.1086 extra (other 1, compaction 1)`, `usage` totals both per group, and the viewer header, `--json` and MCP carry `stats.waste` and `stats.cacheBreaks`. [API reference](https://github.com/jackulau/coding.sh/blob/main/docs/reference/api.md).
- **Sessions.** New `test-tamper` flag: the agent added a skip marker to a test, deleted a test file while tests failed, or changed an assertion and that edit alone turned a failing run green. It reads Edit/Write/apply_patch changes and shell writes (`sed -i`, `>`, `tee`, `rm`, `mv`, `git checkout`), and covers test-runner configs and CI files. New tests and files the agent created itself are not flagged. On 3,957 local sessions it flags 13 (EPISTEME, arXiv 2611.06563). [Concepts](https://github.com/jackulau/coding.sh/blob/main/docs/concepts.md).
- **Harness A/B.** `compare` links each tamper flag to the tool call that made the change and splits tampered passes by whether the agent said it was changing the test: `tampered passes  B 3: disclosed 2, stealth 1`, then one line per pass with the run, file, tool, event id and the agent's words. `--json` adds `tamperAttribution` per run, and the MCP `harness_compare` tool a `tamper` field. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#harness-ab).
- **Judges.** New `no-test-tamper` checklist check, with no model call: it answers no when a test change hid a failure (a skip marker, a test deleted while red, an assertion edit that alone turned the tests green), cites the change and the test runs around it, and quotes what the agent said: `weaken test/sum.test.js by Edit in e42 (turned failing tests green), disclosed: "…"`. Saying why never makes it pass. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#checklists-and-trace-checks).
- **Evals.** `eval audit <task> --experiment <id> --witness <file> --witness-cmd <cmd>` replays a witness test, one that checks a requirement the verifier skips, on every passing run: `claude-tdd: passes 6/10, refuted 3, audited pass rate 30% (3/10)`. The witness must pass the reference 3/3 first. A replay whose verifier no longer passes is `replay-mismatch`, never refuted, and a witness refuting over half the passes is ambiguous and not counted. No model calls (TestJack, arXiv 2610.10619). `--promote` adds it to the verifier, and `eval export`/`import` carry witnesses. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#witness-audits).
- **Harness A/B.** After `eval audit`, `compare` shows each audited arm's raw and audited pass rate, `audited pass  B 60% → 30% (3 refuted, coverage 100%)`. `--audited` counts refuted passes as fails and labels the verdict `verdict (audited)`, with a note when the audit changes it. It needs every pass in both arms replayed, or the raw verdict stands with a coverage note. `--json` and the MCP `harness_compare` tool add the per-arm counts. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#harness-ab).
- **Harness A/B.** `compare` adds a `surface` row: the bytes of instruction text each bundle puts in front of the agent (CLAUDE.md, AGENTS.md, GEMINI.md, skills, rules, system-prompt files, `~/` ones too). When B's is more than 20% bigger, a note asks for a success CI above 0 rather than a tie, since those bytes cost tokens on every turn. `--json` has the sizes per file in `report.surface`. [Compare agents](https://github.com/jackulau/coding.sh/blob/main/docs/how-to/compare-agents.md#why-runs-failed).
- **Evals.** Experiment sessions: `exp session new --name <topic>` starts one in a folder, and each `exp run` there prints its delta against the previous run on the same dataset as it finishes (`pass 0.0% → 100.0%  Δ +100.0pp […]  mcnemar p=0.125`, the grader deltas, the cases fixed and broken, the files changed), with no `exp compare`. `exp session note` records hypotheses and readings, `exp session summary [--json]` prints the timeline. `exp run --watch` reruns on every save of the spec, the agent script, grader files or `watch` globs, aborts a run made stale mid-way without storing it, and regrades the stored outputs with 0 agent calls when only the graders changed. [Evals](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#sessions-deltas-notes-watch).
- **MCP.** `exp_session_note` adds a redacted note to the project's experiment session (the hypothesis before a run, the reading after it) and `exp_session_summary` returns its timeline, paged, with the same blocks as `exp session summary --json`, so an agent can pick an investigation back up after a context reset. Without a session both return a `not_found` error naming `coding.sh exp session new --name <topic>`. [Explore](https://github.com/jackulau/coding.sh/blob/main/docs/guides/explore.md#mcp).
- **Experiments.** `exp regrade <experiment> spec.json` grades a stored experiment's outputs again with new graders, without calling the task, and prints the pass rate before and after, each grader's version change and every run that flipped (`flips 1 of 4 runs: 1 pass → fail`). `exp compare` pins grader versions: a grader that changed version or graded one side only gets a warning above the verdict, and cases left ungraded on one side are listed. [Evals](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#regrade).
- **Experiments.** `exp run matrix.json` runs a spec with `"matrix"` (JSON Pointer axes, every combination) or `"variants"` (named cells plus `"vary"`) against a baseline cell: the cells run interleaved, each is stored as its own experiment with `metadata.matrix`, each is compared with the baseline, and the McNemar p-values are Holm-adjusted over the cells. A cell that differs from the baseline outside `vary`, or touches graders or the dataset, is refused before any call; `--plan` prints the cells and runs nothing, `--cell` runs a subset, `--resume` continues an interrupted matrix. [Evals](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#matrix).
- **Graders.** The `agent-slop` grader flags placeholder code, `as any` and `@ts-ignore`, empty catches, leftover debugging, focused or skipped tests and narrating comments in the lines an agent's diff adds, and `coding.sh judge slop <session|run|experiment>` scores captured work with it, per arm for a compare experiment. Verifiers get the agent's diff in `CODING_SH_AGENT_DIFF`. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#agent-slop).
- **Query.** `coding.sh sql "select …"` runs one read-only SQL query against the SQLite index: one `SELECT` or `WITH` statement on a read-only connection with `query_only` on, with a timeout (`--timeout`, 10 s) and a row cap (`--limit`, 1000). Writes, `ATTACH`, `PRAGMA` and a second statement exit 2; Postgres and ClickHouse stores get an error that points to `export`. `coding.sh export sessions|events|labels` streams rows as JSONL or CSV with the same filters as `sessions`, on every store. [Query and export](https://github.com/jackulau/coding.sh/blob/main/docs/reference/query.md).
- **Privacy.** Sessions count what redaction replaced, by kind, in `stats.redactions` (counts only, never values; blobs and metadata mode included), and a session in which a vendor token was redacted gets the `secret:exposed` tag, since the agent and its model provider still saw it. `coding.sh sessions --flag secret:exposed` lists the credentials to rotate, and `show` prints a `Redacted` row. Sessions stored earlier are counted from their redaction markers. [Storage, sinks and privacy](https://github.com/jackulau/coding.sh/blob/main/docs/guides/privacy.md#privacy).
- **Privacy.** `coding.sh purge --literal <file>` removes a leaked secret from the SQLite store after the fact: event payloads and the search index, session titles and stats, labels, eval docs, settings, blobs (rewritten under a new hash, with references repointed) and the spool, then VACUUMs the index. Values come from a file or stdin and are never printed; `--dry-run` counts the copies. [Storage, sinks and privacy](https://github.com/jackulau/coding.sh/blob/main/docs/guides/privacy.md#privacy).
- **Cost.** `coding.sh usage` marks a cost that counts only some of a row's sessions as a lower bound (`≥$1.50`, replacing the `+` suffix), prints how many sessions have tokens but no cost, and names up to five unpriced models with the `[prices."<model>"]` fix. `--json` is unchanged. [Find expensive sessions](https://github.com/jackulau/coding.sh/blob/main/docs/how-to/expensive-sessions.md).
- **Experiments.** `compare A B --reuse baseline` copies A's finished runs from earlier comparisons instead of running them again (`--reuse both` copies B's too), so several candidates against one baseline pay for it once. A run is reused only when its task, verifier and hidden files, bundle, agent version, attempt, timeout and route hash the same, it finished without an error, and it is newer than `--reuse-max-age` (default 7d). `--dry-run` prints how many runs each arm would reuse and run, and the report notes that reused runs did not run interleaved. [Evals](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#reuse-finished-runs).
- **Evals.** An `executability` grader scores a run by how far it got before its first invalid tool call, one the harness refused to run (a bad argument, an unknown tool, an edit of a file not read yet, a string to replace that is not there, a missing file or command, a denied call). A test that exits 1 ran and is not invalid. The score is the share of steps before that call (its mean is AUC-PEC), and it passes with at most `maxInvalid` invalid calls (its pass rate is TER); `kinds` counts only some kinds (Prefix Executability, arXiv 2610.40444). [Explore guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/explore.md#executability).
- **Query.** `sessions`, `search`, `usage` and `export` take `--where`, one filter language over any session or event field: `agent:codex cost>0.5 tool:Bash ok:false -flag:compaction`, with `OR`, `( )`, wildcards, ranges, `sort:` and `limit:`. `sessions --facets model,tool` counts sessions per value. The viewer API (`?where=`, `/api/facets`) and the MCP tools `sessions_list`, `search` and `usage` (`where`, `facets`) take the same queries. On SQLite a query is one parameterized SQL statement; a typo is a usage error that points at the character. [Query and export](https://github.com/jackulau/coding.sh/blob/main/docs/reference/query.md#filter-with---where)
- **Query.** `--where` on tools, MCP servers, event kinds and `ok` reads indexes instead of scanning events, and their facet counts come from a small per-session table. On a 3.3 GB, 1.4M-event store, `tool:Bash ok:false` takes 5 ms instead of 26 s and the tool, MCP and kind facets 31 ms instead of 8.5 s. The store migrates once on open (about a minute at that size, +4% on disk). `GET /api/events` returns matching events across sessions, newest first and keyset-paged, and `/api/facets` takes `prefix` for autocomplete. [Query and export](https://github.com/jackulau/coding.sh/blob/main/docs/reference/query.md#filter-with---where)
- **Viewer.** The session list has one filter bar for the `--where` language: it completes keys and values (with session counts), runs as you type, and on Enter says what is wrong with a bad query and where. Clauses show as removable chips. The sidebar counts sessions per agent, model, repository, branch, flag, tool, MCP server and event kind; a click adds a value, Alt-click excludes it, and groups fold shut. The query is in the URL, and old `?agent=` and `?q=` links still open. Full-text hits moved out of the list; the list matches sessions by their text. [Explore](https://github.com/jackulau/coding.sh/blob/main/docs/guides/explore.md#viewer)
- **Viewer.** An Events tab next to Sessions lists the events that match the query, newest first, with the session each belongs to and the matched words marked. Enter opens the event's step in its session, and `n` and `N` step through that session's other matches. `GET /api/events` takes `scope=top`. [Explore](https://github.com/jackulau/coding.sh/blob/main/docs/guides/explore.md#viewer)
- **Privacy.** `coding.sh purge --rule <regex>` removes every match of a secret's shape (`sk-ant-api03-[A-Za-z0-9_-]{80,}`) the way `--literal` removes a value, without printing the rule or a match. Purge also scrubs eval run dirs (`~/.coding.sh/runs`), where a kept run holds the agent's transcripts. [Privacy](https://github.com/jackulau/coding.sh/blob/main/docs/guides/privacy.md)
- **Experiments.** `exp run matrix.json --reuse baseline` copies the baseline cell's finished case-trials from earlier experiments instead of running them again, so several matrices against one baseline pay for it once (`--reuse all` copies any cell's). A case-trial is copied only when its case, task spec and files, graders, trial number and timeout all match, within `--reuse-max-age` (default 7d). `--plan` prints how many each cell would copy, and the comparisons warn that the copies did not run interleaved. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#matrix).
- **Compare.** `compare A B --experiment <id> --retry-errors` runs again, in place, only the runs of a stored comparison that errored or failed on infrastructure, and each task, arm and attempt counts once. `--failing <id>[@bundle]` runs only the tasks A failed in that comparison, with a note that the pass rates are conditioned on that failure. `--sample N --seed S` runs a seeded random sample of the tasks. `--json` adds `planned`, `skipped`, `retried` and `selection`, and the consent prompt counts only the runs still to go. [Evals guide](https://github.com/jackulau/coding.sh/blob/main/docs/guides/evals.md#iterate-on-a-comparison).
