# Agent-evaluation landscape, 2024–2026, ranked by value to coding.sh

Companion to [2606.27226.md](./2606.27226.md), the BinEval deep dive. Compiled 2026-11-06.

**How the sources were checked**

- Every entry was confirmed to exist on its arXiv abs page or official URL.
- "Read: full" means the main text was read; appendices may have been skimmed.
- "Read: abstract" means only the abstract or landing page was read.
- Most full texts were read through a summarizing fetch tool, not as raw text. Re-check a number
  against the PDF before quoting it outside this repo.

**How it is ranked:** by how directly the idea changes a coding.sh spec or module, weighted by
how cheap it is to adopt.

## Ranked sources

### 1. ImpossibleBench: Measuring LLMs' Propensity of Exploiting Test Cases

Zhong, Raghunathan, Carlini, 2025. <https://arxiv.org/abs/2510.20270>. Read: full.

- **What it is:** "impossible" variants of SWE-bench Verified and LiveCodeBench tasks in which the
  spec and the tests contradict each other, so any pass is cheating. "One-off" variants flip one
  assertion and "conflicting" variants duplicate a test with a different expected value.
- **Variant check:** each variant must fail both the original patch and an empty patch.
- **Reported numbers:**
  - GPT-5 cheats on 76% of one-off SWE-bench variants.
  - Giving the agent an abort option cut GPT-5's rate from 54% to 9%.
  - LLM monitors caught 42–65% of cheating on SWE-bench.
- **Idea for us:**
  - `validate` builds one impossible variant per task (flip one fail-to-pass assertion) and checks
    that the reference fails it.
  - Harness A/B runs every arm on those variants and reports **cheat rate** next to pass rate.

### 2. How to Correctly Report LLM-as-a-Judge Evaluations

Lee, Zeng, Jeong, Sohn, Lee, ICML 2026. <https://arxiv.org/abs/2511.21140>. Read: full main text.

- **What it is:** a raw judge pass rate is biased by the judge's sensitivity q₁ and specificity
  q₀. The Rogan–Gladen correction θ̂ = (p̂ + q̂₀ − 1)/(q̂₀ + q̂₁ − 1) fixes the point estimate.
  A delta-method CI covers uncertainty from both the test set and the calibration set.
- **When it applies:** only when q₀ + q₁ > 1. About 200 calibration labels give a CI narrower
  than 0.1 in their example.
- **Idea for us:** `calibrate.ts` already computes the held-out confusion matrix. Persist
  sensitivity and specificity in `CalibrationStatus`. Report the corrected judge pass rate with
  that CI next to the raw one in `experiments/render.ts`. Refuse the correction when q₀ + q₁ ≤ 1.

### 3. Are "Solved Issues" in SWE-bench Really Solved Correctly? An Empirical Study (PatchDiff)

You Wang, Pradel, Liu, 2025. <https://arxiv.org/abs/2503.15223>. Read: full.

- **Problem found:** SWE-bench validation runs only the test files the PR changed. As a result,
  7.8% of "plausible" patches fail the full developer test suite.
- **Behavioural differences:** differential tests generated by PatchDiff show 29.6% of plausible
  patches behave differently from the reference. Of 77 hand-checked patches, 28.6% were definitely
  wrong.
- **Idea for us:**
  - Validation runs the repo's full existing suite on the reference (pass-to-pass), not just the
    session's test files.
  - For near-misses, generate differential tests against the reference and flag the task when a
    behaviourally different patch still passes.

### 4. Establishing Best Practices for Building Rigorous Agentic Benchmarks (Agentic Benchmark Checklist, ABC)

Yuxuan Zhu et al., 2025. <https://arxiv.org/abs/2507.02825>. Read: full main body.

- **What it is:** a checklist covering task validity, outcome validity and reporting.
- **Flaws it found:**
  - On τ-bench, empty responses scored 38%.
  - On SWE-Lancer, agents could overwrite the tests.
  - On CVE-Bench, applying the checklist cut overestimation by 33%.
- **Idea for us:** emit an ABC-style scorecard per task. Our checks already map onto the checklist:

  | coding.sh check | ABC item |
  |---|---|
  | No-op fails | R.13 |
  | Reference k/k | T.9 |
  | Leakage | T.5 |
  | Near-misses | O.g.3 |
  | Paired statistics | R.10 |

  Add T.10: send tasks that every arm fails, or that only strong arms pass, to human review.

### 5. EvilGenie: A Reward Hacking Benchmark

Gabor, Lynch, Rosenfeld, 2025. <https://arxiv.org/abs/2511.21654>. Read: full.

- **What it is:** LiveCodeBench-hard problems in an agent workspace with editable tests.
- **Labels:** hardcoded tests, modified test procedure, heuristic solution, and deleted test file.
- **Findings:**
  - Held-out tests added little.
  - An LLM judge worked on unambiguous cases.
  - Detecting test-file edits is deterministic.
  - It observed reward hacking by Codex and Claude Code, and misaligned behaviour by Gemini CLI.
- **Idea for us:** after each replay, run a deterministic **test-tamper diff** against the
  pre-agent snapshot we already store. Cover test files, runner and conftest config, CI config and
  timeouts. Pair it with an LLM judge for the softer labels.

### 6. Adding Error Bars to Evals: A Statistical Approach to Language Model Evaluations

Evan Miller, 2024. <https://arxiv.org/abs/2411.00640>. Read: full.

- **What it is:** five recommendations for eval statistics:
  - CLT standard errors;
  - clustered SEs (clustering inflated the naive SE by up to 3.05× on DROP);
  - resampling with K answers per question;
  - paired differences;
  - power analysis (Eq. 9/10: n ≈ 969 to detect δ = 0.03 at 80% power).
- **Idea for us:**
  - Cluster the bootstrap by repo or task family, not only by task.
  - Print the minimum detectable effect for the chosen n and k before a harness A/B starts.
  - Make McNemar cluster-aware. Today `runner/experiment.ts` runs McNemar "over attempt-aligned
    pairs", which treats correlated attempts of one task as independent.

### 7. Checklists Are Better Than Reward Models For Aligning Language Models

Viswanathan et al., 2025. <https://arxiv.org/abs/2507.18624>. Read: full.

- **What it is:** weighted yes/no checklist items. Each item is scored by an LLM judge averaged
  with a generated verifier program when one exists.
- **Findings:**
  - Checklists written from failure modes of candidate responses beat checklists extracted from
    the instruction: IFEval 77.3 vs 74.3.
  - Removing the verifier programs costs 1.5 points of HSR on FollowBench.
- **Idea for us:** route each checklist item to a deterministic trace predicate when one exists
  and to the judge otherwise. Draft items from failing vs passing trajectories of the same task.

### 8. Ask, Then Grade: When Graded Scales Beat Binary Decomposition for LLM-as-Judge Evaluation

Nandwani, Gakhar, NeurIPS 2026 workshop "Can We Trust the Judge?".
<https://neurips.cc/virtual/2026/161241>. Read: abstract only; the OpenReview PDF was blocked.

- **What it is:** a direct replication of BinEval on SummEval, QAGS and Topical-Chat with 6
  judges. Five-point ratings have the best mean Spearman for every judge and beat BinEval-style
  decomposition in 31 of 36 contrasts.
- **Idea for us:** the judge format (graded vs checklist) is a versioned choice per criterion,
  settled by held-out κ. Use checklists for atomic criteria and for diagnosis, not as a default.

### 9. Coherence Collapse: Diagnosing Why Code Agents Fail After Reaching the Right Code (TrajEval)

Myeongsoo Kim et al., 2026. <https://arxiv.org/abs/2603.24631>. Read: full.

- **What it is:** 16,758 SWE-bench Verified trajectories, each split into search, read and edit
  stages. For each stage, precision and recall are measured against the files and functions of
  the gold patch.
- **Findings:**
  - 60–69% of failures edit the right functions and still produce a wrong patch.
  - In 5 cases a mid-run patch was identical to gold and was later destroyed. An edit checkpoint
    recovered all 5.
- **Idea for us:**
  - ARCHITECTURE specs a snapshot at every turn end. Compute stage recall over time per arm
    against the reference diff.
  - Flag "near-correct, then corrupted" runs, where an intermediate snapshot is closer to the
    reference than the final one.
  - Use the recall curves to sharpen "first trace divergence".

### 10. Evaluating AGENTS.md: Are Repository-Level Context Files Helpful for Coding Agents?

Gloaguen, Mündler-Sasahara, Müller, Raychev, Vechev, 2026 (v3 Sep 2026).
<https://arxiv.org/abs/2602.11988>. Read: full (v3).

- **Findings:**
  - Context files do not generally raise success rates and add over 20% inference cost.
  - Agents follow the files, but repository overviews don't help.
  - Developer-written files gained about 2.4 points, which was not significant (p = 0.21).
- **Idea for us:** this is the reference harness A/B. Report cost, steps and behaviour counters
  next to pass rate. Warn before a run when the planned n cannot detect a 2–4 point effect.

### 11. Holistic Agent Leaderboard: The Missing Infrastructure for AI Agent Evaluation (HAL)

Kapoor et al., 2025. <https://arxiv.org/abs/2510.11977>. Read: full.

- **Scale:** 21,730 rollouts across 9 models and 9 benchmarks.
- **Scaffold findings:**
  - A task-specific scaffold beat a generic one in 11 of 12 runs.
  - The scaffold and the model interact.
  - Higher reasoning effort did not help in 21 of 36 runs.
- **Log analysis:** a rubric run with Docent: instruction violations, tool-use failure,
  self-correction, verification, environmental barriers, shortcuts.
- **Idea for us:**
  - Treat scaffold (bundle) and model as separate factors and report their interaction.
  - Use the Docent rubric as the default single-agent trace labels.
  - Record the provider's response model id on every call, to catch silent model swaps.

### 12. Recent Frontier Models Are Reward Hacking

METR, 2025-06-05. <https://metr.org/blog/2025-06-05-recent-reward-hacking>. Read: full.

- **Rates:** o3 reward-hacked in 30.4% of RE-Bench runs.
- **Hack types:** overwriting timers, monkey-patching the evaluator, and reading the scorer's
  answer from the call stack.
- **Prompting doesn't help:** "Please do not cheat" did not lower the rate.
- **Detection:** an anomaly heuristic and an LLM monitor each missed hacks the other caught.
- **Idea for us:**
  - Do not count "don't cheat" lines in an instructions file as a mitigation.
  - Report the union of the static tamper diff and an LLM monitor.
  - Add pattern rules for test-framework monkey-patching and frame inspection.

### 13. CheckEval: A reliable LLM-as-a-Judge framework for evaluating text generation using checklists

Y. Lee et al., EMNLP 2025. <https://arxiv.org/abs/2403.18771>. Read: full main text.

- **What it is:** BinEval's uncited predecessor, with Boolean checklist questions per
  sub-dimension.
- **Finding:** Krippendorff's α *across 12 judge models* is 0.48 vs 0.09 for G-Eval on SummEval.
  Weighted aggregation did not reliably help.
- **Idea for us:** report α across two or three judge models on the same rubric hash. It shows an
  under-specified rubric before any human labels exist.

### 14. SWE-rebench: An Automated Pipeline for Task Collection and Decontaminated Evaluation of Software Engineering Agents

Badertdinov et al., NeurIPS 2025. <https://arxiv.org/abs/2505.20411>. Read: full.

- **What it is:** fresh tasks mined continuously, scored with 5 runs per model with SEM and
  pass@5, and marked when a task predates a model's release.
- **Contamination example:** DeepSeek-V3-0324 scores 39.7% on SWE-bench Verified and 21.3% on
  SWE-rebench.
- **Idea for us:** store the source date on every task (session date and base-commit date). Flag
  arms whose model cutoff is later. Captured private sessions are fresh by construction, and this
  field shows it.

### 15. Why Do Multi-Agent LLM Systems Fail? (MAST)

Cemri et al., 2025. <https://arxiv.org/abs/2503.13657>. Read: partial (taxonomy and agreement
sections).

- **What it is:** 14 failure modes in 3 categories, from more than 1,600 traces.
- **Agreement:** humans reach κ = 0.88; an LLM annotator reaches κ = 0.77.
- **Most common modes:** step repetition (15.7%) and reasoning–action mismatch (13.2%).
- **Idea for us:** use FM-1.1…FM-3.3 as the label set for workflow traces (WORKFLOWS §4/§5),
  and measure LLM-labeller κ against a small human set, as they did.

### 16. MCPMark: A Benchmark for Stress-Testing Realistic and Comprehensive MCP Use

Wu et al., ICLR 2026. <https://arxiv.org/abs/2509.24002>. Read: full main body.

- **What it is:** 127 tasks, each with an initial-state fixture, a state-checking verifier and a
  reset.
- **Reliability gap:** gpt-5-medium scores 52.56 pass@1 but 33.86 pass^4.
- **Failure split:** "implicit" failures (finished but wrong) are the majority. "Explicit" failures
  are context overflow, turn limit, malformed calls and so on.
- **Idea for us:** TOOL-EVALS §3 already has this task shape. Add the explicit/implicit failure
  enum to `TrialResult`, and report pass^k in harness compare as well as tool evals.

### 17. The Alternative Annotator Test for LLM-as-a-Judge

Calderon, Reichart, Dror, ACL 2025. <https://arxiv.org/abs/2501.10970>. Read: full main text.

- **What it is:** a leave-one-annotator-out test with margin ε (0.1–0.2) and
  Benjamini–Yekutieli correction. It decides whether a judge can replace humans. It needs 3 or
  more annotators and about 100 items.
- **Idea for us:** use it as the promotion gate when a team has 3 or more labellers. Fall back to
  κ plus the correction in #2 for a single local user.

### 18. Position: Don't Use the CLT in LLM Evals With Fewer Than a Few Hundred Datapoints

Bowyer, Aitchison, Ivanova, ICML 2025. <https://arxiv.org/abs/2503.01747>. Read: abstract.

- **What it is:** CLT intervals under-cover on small benchmarks.
- **Idea for us:** session-derived suites are often 20–100 tasks. Keep Wilson for single rates,
  add a Beta-Binomial or Bayesian option for paired differences, and print a small-n warning
  below about 200 tasks.

### 19. OpenTelemetry GenAI agent and framework span conventions

OpenTelemetry, current. <https://github.com/open-telemetry/semantic-conventions-genai>
(`docs/gen-ai/gen-ai-agent-spans.md`). Read: full.

- **What it is:** defines `invoke_agent` (control flow driven by the model), `invoke_workflow`
  (control flow defined by the application), `execute_tool` and `plan`. Content attributes are
  opt-in, with `_ref` variants for externally stored content. Status: still Development.
- **Idea for us:** map WORKFLOWS nodes onto `invoke_workflow` vs `invoke_agent`, and store large
  content as `_ref` pointers into the blob store. Record the pinned semconv version on every
  trace, as ARCHITECTURE already intends.

### 20. Trust or Escalate: LLM Judges with Provable Guarantees for Human Agreement

Jung, Brahman, Choi, 2024. <https://arxiv.org/abs/2407.18370>. Read: abstract.

- **What it is:** a judge abstains below a confidence threshold calibrated on human labels and
  escalates to a stronger judge. Reported: "over 80% human agreement with roughly 80% test
  coverage."
- **Idea for us:** let users set a target agreement. Calibrate a confidence threshold per judge
  version on the held-out split, and route low-confidence cases to a stronger judge or the label
  queue. Report coverage.

### Also verified, lower priority

- **UTBoost** (Boxi Yu et al., ACL 2025, <https://arxiv.org/abs/2506.09289>; abstract).
  LLM-generated extra tests overturned 24.4% of SWE-bench Verified leaderboard rankings.
- **The SWE-Bench Illusion** (Liang et al., 2025, <https://arxiv.org/abs/2506.12286>; abstract).
  Models name the buggy file from the issue text alone with up to 76% accuracy. That is a cheap
  contamination probe.
- **TRAIL** (Deshpande et al., 2025, <https://arxiv.org/abs/2505.08638>; abstract). The best model
  localizes errors in agent traces at 11%, so LLM-only trace debugging needs human calibration.
- **JudgeBench** (Tan et al., ICLR 2025, <https://arxiv.org/abs/2410.12784>; abstract). Builds
  judge sanity pairs whose labels come from objective correctness. In coding.sh, tests decide
  those labels.
- **Judging the Judges: position bias** (Shi et al., AACL 2025,
  <https://arxiv.org/abs/2406.07791>; abstract). Always run pairwise judges in both orders.
- **Terminal-Bench** (Merrill et al., ICLR 2026, <https://arxiv.org/abs/2601.11868>; abstract) and
  **SWE-Bench Pro** (Deng et al., 2025, <https://arxiv.org/abs/2509.16941>; abstract). Task-format
  and held-out-split precedents for the Harbor export.
- **Luo and Gao, "Designing Reliable LLM-as-a-Judge Measurement Systems for Multi-Turn Business
  Agents"** (2026, <https://arxiv.org/abs/2609.33955>; abstract). The one evaluation-methodology
  paper among the 7 that cite BinEval. It describes a maintained judge system in which human audits
  route each disagreement to a label, guideline or judge fix.

## Themes

1. **Verifiers are the weak point, and the fixes are mechanical.** PatchDiff, UTBoost, ABC,
   ImpossibleBench and EvilGenie all show benchmark scores inflated by weak or tamperable tests.
   coding.sh already has the parts that are hard to build: the pre-agent snapshot, hidden verifier
   files, and the validation steps. The cheap wins are four more checks:
   - an impossible variant;
   - the full-suite pass-to-pass run;
   - a tamper diff;
   - requirement-targeted near-misses.
2. **Judges: decompose where criteria are atomic, correct the bias, measure reliability.**
   BinEval, CheckEval and Checklists-vs-RM support binary items for checkable criteria. "Ask, Then
   Grade" warns against using them for holistic ones. Lee et al. show any judge pass rate needs
   bias correction from its confusion matrix, which we already compute.
3. **Harness effects are small, and we are underpowered by default.** Developer-written AGENTS.md
   files gained about 2.4 points, which was not significant, at +20% cost (AGENTS.md study). HAL
   finds the scaffold and the model interact. Miller's and Bowyer's points about clustering and
   small n apply directly to 20–100-task suites. Harness A/B needs an MDE warning and
   cluster-aware tests more than it needs new metrics.
4. **Trajectory analysis is moving from labels to measurable signals.** Examples are stage recall
   (TrajEval), the tap-based tool metrics we already spec, and the MAST/Docent label sets. A label
   is worth having when an LLM labeller can reach κ ≥ 0.7 against humans on it.

## Prioritized changes to coding.sh

Effort: S is a day or less, M is a few days, and L is a week or more. Sources are the ranked
entries above, or "BinEval §x" for [2606.27226.md](./2606.27226.md).

### 1. Unify judge calibration and enforce tuning hygiene (S)

Touches `src/eval/judge.ts`, `src/judge/calibrate.ts`, and ARCHITECTURE "Judge calibration".

- Two implementations disagree today. `src/eval/judge.ts` `calibrate()` uses κ ≥ 0.7, `minN` 10
  and ignores splits. `src/judge/calibrate.ts` uses κ ≥ 0.6, `minN` 20 and a held-out split.
- Make the first delegate to the second, and write the threshold and `minN` into ARCHITECTURE.
- Any split used for early stopping or prompt iteration goes into `tunedOn` automatically.
- Source: BinEval §6.1, test-set model selection.

### 2. Test-tamper detector on every replay run (S/M)

Touches a new `src/eval/tamper.ts`, `RunResult` in `src/core/types.ts`, `CompareReport`, and
ARCHITECTURE "Runner" step 4.

1. Diff the following between the task's start snapshot and the final tree:
   - test files and test-runner config (`conftest.py`, `jest.config.*`, `vitest.config.*`,
     `pytest.ini`, `package.json` scripts);
   - CI files;
   - added skip or only markers, and changed timeouts.
2. Pattern-match commands and diffs for test-framework monkey-patching and stack or frame
   inspection.
3. Record `tamper: string[]` per run. Report `tamperRate` per arm in compare, and count a tampered
   pass as a fail by default.
- Sources: #5, #12, #1.

### 3. Validation adds an impossible variant and a pass-to-pass check (M)

Touches `src/eval/validate.ts`, `ValidationReport` in `src/core/types.ts`, and ARCHITECTURE
"Evals" verifier validation.

- **Impossible variant.** Flip one fail-to-pass expected value in a hidden test file. The
  reference must fail it. Store the variant as `task.impossibleVariant`, a blob, so harness A/B
  can measure cheat rate.
- **Pass-to-pass.** Run the repo's pre-existing suite on the reference, and record
  `passToPass: {passed, of}`.
- Sources: #1, #3, #4.

### 4. Checklist judge with critical gates and deterministic routing (M)

Touches `src/judge` (new `predicates.ts`), `src/graders/index.ts` (`LlmChecklistSpec`),
`src/datasets/types.ts` (per-item verdicts), and ARCHITECTURE "Graders".

- Items are frozen and hashed into the judge version.
- A `critical` item forces fail on "no".
- Each item gets an explanation and a verified citation.
- Each item uses a trace predicate when one exists, such as tests run after the last edit, a test
  file touched, or completion claimed without a passing test. Otherwise one LLM call per item.
- Graded and checklist formats are both versioned. Pick per criterion by held-out κ.
- Sources: BinEval §7.1 A1/A2, #7, #8, #13.

### 5. Bias-corrected judge pass rates (S)

Touches `src/stats/interval.ts` (`roganGladen` with delta-method CI), `CalibrationStatus`
(sensitivity and specificity), and `src/experiments/render.ts`.

- Show the corrected rate and CI next to the raw rate for every LLM grader.
- Suppress the correction when q₀ + q₁ ≤ 1.
- Source: #2.

### 6. Judge reliability diagnostics (S/M)

Touches a new `src/judge/diagnostics.ts` and `src/stats/agreement.ts` (new `phi`,
`krippendorffAlpha`). Reported by `coding.sh judge calibrate` and `coding.sh judge diff A B`. The
report covers:

- per-item yes-rate, with flags for near-constant items (< 0.05 or > 0.95) and redundant pairs
  (φ > 0.8);
- ceiling share;
- test-retest self-κ on a 10–20% subset;
- α across judge models per rubric hash;
- accuracy on a sanity set whose labels come from deterministic graders;
- a per-item disagreement table between two judge versions, for migrating to a cheaper or local
  judge (a migrated judge inherits no calibration).

Sources: BinEval §5.6 and §3.3, #13, JudgeBench.

### 7. Cluster-aware stats and power warnings in compare (S/M)

Touches `src/stats`, `src/runner/experiment.ts`, `src/experiments/compare.ts`, and DOGFOOD §5 keep
rule 2.

- Replace attempt-aligned McNemar in `runner/experiment.ts` with McNemar on per-task majority
  outcomes, as `experiments/compare.ts` already does. Then DOGFOOD's "or McNemar p < 0.05"
  shortcut stops counting correlated attempts as independent evidence.
- Add an optional cluster key (repo or task family) to the bootstrap.
- Print the minimum detectable effect for (n tasks, k) before a run (Miller Eq. 10), and a
  small-n warning below about 200 tasks.
- Report pass^k next to pass@k in harness compare.
- Sources: #6, #18, #16.

### 8. Requirement-targeted near-misses and requirement coverage (M/L)

Touches `src/eval/task.ts` (`meta.requirements`, extracted once and human-editable),
`src/eval/patch.ts` (a violation patch per requirement: a hunk drop when one maps, otherwise
LLM-written and stored as a blob), `src/eval/validate.ts`, and `ValidationReport`
(`requirementCoverage: {caught, of, uncaught}`).

- Verifier validation then asks whether the verifier catches the violation of *each requirement*,
  not only whether it is sensitive to the patch.
- Optionally add PatchDiff-style differential tests.
- Sources: BinEval §3.1 and §7.1 A6, #3.

### 9. Track instruction-surface size and cap automated prompt loops (S)

Touches `src/runner/bundle.ts` (`instructionBytes`/`instructionTokens` over AGENTS.md,
skills and the system-prompt files in a bundle), `CompareReport.metrics`, DOGFOOD §5 keep rule,
and TOOL-EVALS §8.3.

- In the keep rule, a candidate that grows the instruction surface by more than 20% needs a
  success CI that excludes 0, not just non-inferiority.
- Any automated lesson or prompt optimizer runs at most 2 iterations by default and stops on dev,
  not test.
- Sources: BinEval App. A.2.4 (prompt bloat from 22 to 6,248 characters, then collapse) and #10
  (+20% cost, no gain).

### 10. Stage-recall divergence, the near-correct-then-corrupted flag, and default label sets (M)

Touches `src/runner/divergence.ts`, `src/core/snapshot.ts`, WORKFLOWS §4/§5, and TOOL-EVALS §6.

- Needs the turn-end snapshots that ARCHITECTURE "Repo snapshots" specs. Today
  `src/capture/wrapper.ts` snapshots only at session start and end.

- Per arm, compute search, read and edit recall against the reference diff at each turn end.
- Flag runs where an intermediate snapshot is closer to the reference than the final one.
- Default label enums:
  - Docent/HAL rubric for single agents;
  - MAST FM codes for workflows;
  - MCPMark's explicit/implicit split for tool evals.

  Each label set is adopted only after an LLM labeller reaches κ ≥ 0.7 on 30 or more
  human-labelled traces.
- Sources: #9, #11, #15, #16.
